# 02~11 연구 문서 → 자동투자 코드 매핑

작성일: 2026-07-15

이 문서는 `ai_prompt/02_트레이딩팀.md`부터 `11_추측디코딩.md`까지의
아이디어를 현재 프로젝트에 반영한 위치와 한계를 함께 기록한다. `ai_prompt/`은
연구·설계 문서이고, 실제 멀티모델 역할 프롬프트는 별도의 `agent/`이다.

상태 표기:

- **구현**: 코드와 단위 테스트가 있으며 실제 분석 경로에서 사용한다.
- **연구 전용**: 계산은 구현했지만 주문 생성에는 사용하지 않는다.
- **부분 구현**: 안전한 기반은 있으나 논문 전체 재현은 아니다.
- **미구현**: 데이터·모델·브로커 능력이 없어서 일부러 자동 주문에 넣지 않았다.

## 현재 실제 의사결정 흐름

`ENABLE_NVIDIA_NEMOTRON_AGENTS=true`일 때 한 이벤트는 다음 순서로 동작한다.

```text
이벤트/종목
  → 가격·OHLCV·재무 수집
  → 종목별 ResearchPacket 고정 + 입력 해시
  → 증거 분석 모델 → Bull/Bear·Risk 모델 → 최종 비교 모델(주문 권한 없음)
  → LMSR / 팩터 / 기술 규칙 / SDE / Kelly / Python 위험 게이트
  → 주문 규격 생성 → Toss 주문 → 주문/예측/감사 원장
```

핵심 변경은 `main.py`가 **에이전트 모델 호출 전에** 각 종목의 가격·OHLCV·재무·기술지표
스냅샷을 만들도록 한 것이다. 이전의 `make_mock_universe()` 무작위 팩터는 메인
경로에서 제거했다. 누락 데이터는 무작위 값이 아니라 `NaN → 중립 점수`로 처리되고,
어떤 데이터가 없는지는 패킷의 `missing_modalities`에 남는다.

`ENABLE_NVIDIA_NEMOTRON_AGENTS=false`이면 기존 듀얼 공급자로 돌아가지 않고 해당 이벤트의 신규 매수를 차단한다.
새 종목별 패킷은 Super 분석, Ultra Bull/Bear·Risk, GLM 최종 비교로 이어지는 멀티모델 에이전트 경로에 전달된다.

### 06_구현가이드.md

`main.py`와 `strategy/agentic/orchestrator.py`의 경계가 이 문서의 핵심을 따른다.

```text
Gemini 리서치/구조화 제안
  → Python risk / technical / sizing
  → order_builder
  → TossClient
  → audit·trade·forecast ledger
```

Gemini 역할은 주문 API·파일 수정 권한이 없고 `direct_order_execution=false`를 registry와
프롬프트 로더가 확인한다. 외부 TradingAgents 저장소를 실제 import하거나 commit pin한
구현은 **없다**.

| `alpha=1-TV`, `E[N]`, speedup | `mean_acceptance_rate`, `expected_emitted_tokens`, `expected_walltime_speedup` | 연구 전용 | gamma/cost 가정에 따른 벤치마크 계산이다. |
| capability gate/latency | `GeminiAPI2Client.capabilities`, `orchestrator.py:_run_agent` | 구현 | Gemini managed API는 token-level speculation=false이고, 실제 agent latency를 audit에 남긴다. |
| Gemini에서 실제 speculative decoding | 없음 | 의도적으로 미구현 | API가 target/draft logits, 동일 tokenizer, KV cache를 제공하지 않는다. 원격 API를 두 번 호출해 흉내 내지 않는다. |

## 운영 설정과 안전한 시작 순서

새 설정은 `config.py`에서 읽는다.

```env
# 역할별 멀티모델 팀을 실제 분석 경로에 사용
ENABLE_NVIDIA_NEMOTRON_AGENTS=true
NVIDIA_SUPER_MODEL=nvidia/nemotron-3-super-120b-a12b
NVIDIA_NEMOTRON_MODEL=nvidia/nemotron-3-ultra-550b-a55b
NVIDIA_FINAL_MODEL=z-ai/glm-5.2

# ResearchPacket 지표 convention
RESEARCH_OHLCV_BARS=260
RESEARCH_RSI_PERIOD=20
RESEARCH_SMA_SHORT_PERIOD=50
RESEARCH_SMA_LONG_PERIOD=200

# 통계 리드래그는 기본 off; 켜도 research-only 후보 생성이다.
ENABLE_LEAD_LAG_RESEARCH=false
LEAD_LAG_MAX_LAG=3
LEAD_LAG_FDR_ALPHA=0.05
LEAD_LAG_MAX_SYMBOLS=20
```

권장 순서:

1. `DRY_RUN=true`에서 `python main.py --once`를 실행한다.
2. `trades.jsonl`의 `research_packet_hash`, `research_sources`, `reasoning_fusion`,
   `forecast_record`를 확인한다.
3. `data/agentic/audit.jsonl`에서 prompt/input/response hash, model, latency를 확인한다.
4. `ENABLE_LEAD_LAG_RESEARCH=true`는 충분한 실제 OHLCV가 확보된 dry-run에서만 먼저 확인한다.
5. 실제 주문 전에는 수수료·슬리피지·실제 체결 outcome을 포함한 별도 backtest/walk-forward를
   완료한다.
