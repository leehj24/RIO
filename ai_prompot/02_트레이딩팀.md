## 역할별 입력 데이터와 분석 방법

TradingAgents는 단순히 여러 LLM에게 같은 질문을 반복하는 구조가 아니다. 각 에이전트에 서로 다른 데이터 접근 권한, 목표, 도구와 보고서 작성 책임을 부여한다. 논문은 이를 펀더멘털·심리·뉴스·기술 분석가, 연구원, 트레이더, 위험관리자로 구분하며, 실제 실행에서는 Bull/Bear 연구원과 공격적·중립·보수적 위험관리 관점이 각각 별도 에이전트로 동작한다. ([arXiv][1])

### 기술 분석가

기술 분석가는 모든 지표를 무조건 LLM 프롬프트에 넣지 않는다. 먼저 가격과 거래량을 조회한 뒤, 현재 자산을 분석하는 데 필요한 지표를 선택하고 각 지표의 상세 데이터를 도구로 조회한다. 이후 지표들을 모멘텀, 추세, 변동성, 거래량, 가격 행동 등의 범주로 묶어 자연어 보고서를 만든다. ([arXiv][1])

부록의 AAPL 실행 예시에서는 다음 지표가 선택됐다.

| 분석 범주    | 선택 지표           | 분석 목적                   |
| -------- | --------------- | ----------------------- |
| 모멘텀      | RSI             | 과매수·과매도 및 매수 강도 판단      |
| 추세 강도    | ADX             | 현재 추세가 강해지는지 약해지는지 판단   |
| 변동성      | Bollinger Bands | 가격 범위 확대와 돌파 가능성 분석     |
| 추세·모멘텀   | MACD            | 단기·장기 추세 변화와 방향 확인      |
| 가격·거래량   | VWMA            | 거래량을 반영한 평균가격과 현재 가격 비교 |
| 변동성      | ATR             | 일별 가격 변동 범위 측정          |
| 추세 전환    | Supertrend      | 추세 방향과 반전 가능성 탐색        |
| 순환·가격 이탈 | CCI             | 평균가격으로부터의 이탈과 과열 상태 분석  |

논문의 기술 분석 과정은 다음과 같이 정리할 수 있다.

```text
OHLCV 데이터 조회
  → 현재 시장의 가격·거래량 특징 요약
  → 분석 목적별 기술지표 선택
  → 지표별 데이터 도구 호출
  → 지표 간 일치·충돌 확인
  → 추세·과열·변동성·진입 위험 보고서 작성
```

부록에서 기술 분석가는 `get_YFin_data`로 가격 데이터를 조회하고, `get_stockstats_indicators_report`에 종목·지표·기준일을 넘겨 지표별 보고서를 받는다. 따라서 LLM이 숫자를 직접 계산하기보다는 **도구가 계산한 결과를 LLM이 선택·해석·종합하는 도구 증강 분석**에 가깝다. ([arXiv][1])

다만 부록 예시에서는 선택 목록에 `VWMA`가 들어가지만 최종 보고서에는 거래량 지표로 `VR`이 서술된다. 이는 지표 선택 단계와 보고서 생성 단계 사이의 명칭 또는 데이터 정합성을 검증해야 한다는 사례로 볼 수 있다. 

> 논문은 MACD, RSI, Bollinger Bands 등 60개 기술지표를 사용할 수 있다고 설명하지만 각 지표의 수식, 기간과 매매 임계값은 제시하지 않는다. 따라서 RSI 14일, MACD 12·26·9와 같은 값을 사용했다고 논문 내용으로 단정하면 안 된다.

### 펀더멘털 분석가

펀더멘털 분석가는 단순한 PER·PBR 비교보다 넓은 범위의 재무 데이터를 결합한다. 부록의 AAPL 예시에서 사용한 분석 항목은 다음과 같다. ([arXiv][1])

* 기업 프로필, 업종, 시가총액, 발행주식 수
* 52주 가격 범위와 5일·13주·26주·52주·연초 이후 수익률
* 시장 벤치마크 대비 상대수익률
* 매출총이익률, 영업이익률, 순이익률
* ROE와 ROA
* 3년·5년·분기 기준 EPS 및 매출 성장률
* 유동비율, 당좌비율
* 장기부채비율과 총부채비율
* P/E, P/B, P/CF
* 주당현금흐름, 배당수익률, 배당성향
* 내부자 심리와 내부자 매매 내역

분석가는 재무지표를 각각 독립적으로 평가하지 않고 상충 관계를 설명한다. 예를 들어 높은 ROE와 이익률은 강점으로, 유동비율 1 미만과 높은 레버리지는 위험으로, 높은 P/E와 P/B는 성장 기대 또는 과대평가 가능성으로 동시에 해석한다. 마지막에는 `강점`, `약점`, `밸류에이션`, `투자 시 고려사항`을 구분해 보고서를 작성한다. ([arXiv][1])

부록에서 확인되는 주요 도구 호출은 다음과 같다.

```text
기업 프로필 조회
재무지표 이력 조회
기본 재무비율 조회
내부자 심리 조회
내부자 거래 조회
```

### 뉴스 분석가

뉴스 분석가는 종목 관련 기사만 요약하지 않는다. 기업 뉴스와 함께 거시경제, 금리·인플레이션, 정부 정책, 지정학적 위험, 공급망과 산업 동향을 연결한다. AAPL 예시에서는 EODHD와 Finnhub 뉴스를 조회하고, Apple뿐 아니라 TSM·GOOGL·AMZN 등 관련 기업의 뉴스도 함께 조사했다. ([arXiv][1])

뉴스 분석 절차는 다음과 같다.

```text
기업 직접 뉴스
  + 경쟁사·공급망 뉴스
  + 금리·물가·정부 정책
  + 지정학적 사건
  + 산업 및 기술 변화
  → 해당 사건이 매출·비용·수요·밸류에이션에 미칠 경로 분석
```

따라서 뉴스의 긍정·부정 분류만 수행하는 것이 아니라, 뉴스가 가격에 영향을 미치는 **경제적 전달 경로**를 설명하도록 설계돼 있다.

### 심리 분석가

심리 분석가는 Reddit과 기타 소셜 데이터, 별도의 언어모델이 산출한 정규화 감성 점수, 게시물 수와 참여도를 함께 본다. 부록 예시는 날짜별 감성 점수와 감성 데이터 개수를 함께 비교해, 높은 긍정 점수라도 표본 수가 적으면 신뢰도가 제한될 수 있음을 드러낸다. ([arXiv][1])

특히 Reddit 게시물이 검색되지 않았을 때 이를 곧바로 중립 심리로 처리하지 않고, **주요 이슈 부재 또는 데이터 수집 공백일 수 있다**고 구분한다. 이는 `데이터 없음`과 `중립적 데이터`를 분리해야 한다는 중요한 구현 원칙이다. ([arXiv][1])

## ReAct 기반 도구 사용 절차

모든 에이전트는 추론과 행동을 반복하는 ReAct 방식을 따른다. 에이전트는 공유 상태를 읽고 필요한 정보를 판단한 뒤, 데이터 조회 도구를 호출하고, 반환된 관찰 결과를 이용해 보고서를 갱신한다. ([arXiv][1])

```text
1. State
   현재 종목, 기준일, 이전 보고서와 포트폴리오 상태를 읽는다.

2. Reason
   현재 역할에서 부족한 정보와 확인할 가설을 결정한다.

3. Action
   가격·지표·뉴스·심리·재무 API 또는 검색 도구를 호출한다.

4. Observation
   도구가 반환한 수치와 문서를 검토한다.

5. Synthesis
   서로 일치하는 신호와 충돌하는 신호를 분리한다.

6. Report
   핵심 수치, 근거, 위험과 권고를 구조화된 보고서로 저장한다.

7. Debate or Decision
   필요한 경우 다른 관점의 에이전트와 토론하거나 다음 역할에 결과를 넘긴다.
```

부록의 하루 실행 로그에는 보고서뿐 아니라 도구 이름, 호출 인자, 종목, 조회 기간과 기준일이 기록돼 있다. 논문은 이러한 로그가 의사결정의 해석과 디버깅에 도움을 준다고 주장한다. ([arXiv][1])

## 구조화된 보고서와 전역 상태

TradingAgents는 모든 정보를 하나의 긴 채팅 기록에 누적하지 않는다. 일상적인 역할 간 전달은 구조화된 보고서로 처리하고, 논쟁이 필요한 연구팀과 위험관리팀만 자연어 대화를 사용한다. 각 역할은 전역 상태에서 필요한 보고서만 읽고 자신의 결과를 다시 별도 상태에 기록한다. 

논문은 정확한 필드명을 공개하지 않지만, 개념적으로는 다음과 같은 상태 구조로 해석할 수 있다.

```yaml
global_state:
  ticker: AAPL
  analysis_date: 2024-11-19

  analyst_reports:
    market_report:
    sentiment_report:
    news_report:
    fundamentals_report:

  investment_debate:
    bull_arguments:
    bear_arguments:
    debate_history:
    facilitator_result:

  trader:
    action: BUY | SELL | HOLD
    trade_report:
    proposed_timing:
    proposed_size:

  risk_debate:
    aggressive_view:
    neutral_view:
    conservative_view:
    debate_history:
    risk_adjustment:

  final_decision:
    action:
    manager_report:
```

> 위 필드명은 논문이 그대로 제시한 데이터 스키마가 아니라, 논문의 구조화된 통신 프로토콜을 구현 가능한 형태로 옮긴 해석이다.

## Bull–Bear 연구 토론

연구팀은 동일한 분석 보고서를 바탕으로 정반대 관점의 논리를 만든다.

* **Bull 연구원**은 성장 잠재력, 강한 재무성과, 긍정적 심리, 기술적 상승 신호와 경쟁우위를 강조한다.
* **Bear 연구원**은 고평가, 유동성·레버리지 위험, 내부자 매도, 경쟁 심화, 지정학적 위험과 과매수 상태를 강조한다.

두 연구원은 촉진자가 정한 `n`회의 자연어 토론을 수행한다. 토론 종료 후 촉진자가 전체 대화 기록을 검토해 우세한 관점을 구조화된 연구 결과로 저장한다. ([arXiv][1])

이를 알고리즘 형태로 나타내면 다음과 같다.

```text
analyst_reports 조회

for round in 1..n:
    bull_argument = Bull(analyst_reports, bear_argument)
    bear_argument = Bear(analyst_reports, bull_argument)
    debate_history.append(bull_argument, bear_argument)

research_result = Facilitator(debate_history)
```

논문은 토론 횟수를 `n`으로 표현하지만 실제 실험에서 사용한 고정 횟수와 촉진자의 승자 선정 기준은 명확히 공개하지 않는다. ([arXiv][1])

## 위험관리 토론과 최종 승인

트레이더가 만든 매매안은 곧바로 실행되지 않는다. 위험관리팀이 트레이더의 결정과 근거 보고서를 조회하고 세 가지 위험 성향으로 다시 검토한다. ([arXiv][1])

| 위험 관점                 | 역할                         |
| --------------------- | -------------------------- |
| 공격적·Risk-seeking      | 높은 변동성을 감수하고 상승 기회를 최대한 활용 |
| 중립적·Neutral           | 기대수익과 하방위험을 균형 있게 반영       |
| 보수적·Risk-conservative | 과대평가·변동성·손실 가능성을 우선 통제     |

부록의 중립 위험관리자는 전량 진입 대신 분할매수, 손절매, 헤지, 섹터·지역 분산 등을 절충안으로 제시한다. 최종 펀드매니저는 위험 토론 결과를 검토하고 트레이더의 결정과 보고서를 승인하거나 조정한다. ([arXiv][1])

다만 논문은 손절 비율, 최대 포지션 비중, 변동성 한도와 같은 **수치화된 위험 규칙**을 제시하지 않는다. 위험관리는 주로 자연어 토론과 펀드매니저의 최종 판단으로 설명된다.

## 모델 역할 분배

논문은 모든 작업에 동일한 LLM을 사용하지 않고 작업 난도에 따라 모델을 분리한다.

* 빠른 모델: API 데이터 조회, 검색, 요약, 표를 텍스트로 변환하는 작업
* 깊은 추론 모델: 분석 보고서 작성, 연구 토론, 거래 판단, 위험 검토

예시로 빠른 모델에는 GPT-4o-mini와 GPT-4o, 깊은 추론 모델에는 o1-preview가 언급된다. 분석가·연구원·트레이더의 핵심 판단에는 깊은 추론 모델을 사용하고, 외부 도구 호출과 데이터 수집에는 상대적으로 빠른 모델을 배치한다. ([arXiv][1])

이 구조의 목적은 전체 에이전트를 가장 비싼 모델로 실행하지 않고, **검색 비용과 추론 품질을 역할별로 최적화하는 것**이다.

## 비교 기준 전략

논문은 TradingAgents를 다음 다섯 전략과 비교한다. 

| 전략           | 매매 원리                              |
| ------------ | ---------------------------------- |
| Buy and Hold | 선택한 자산에 동일 금액을 투자하고 기간 끝까지 보유      |
| MACD         | MACD선과 시그널선의 교차를 매수·매도 신호로 사용      |
| KDJ + RSI    | 스토캐스틱 계열 KDJ와 RSI로 과매수·과매도 상태 탐지   |
| ZMR          | 가격이 0 기준선에서 이탈했다가 평균으로 회귀하는 움직임 사용 |
| SMA          | 단기·장기 단순이동평균 교차를 추세 신호로 사용         |

그러나 각 전략의 이동평균 기간, RSI 임계값, KDJ 설정과 ZMR 계산 방식은 구체적으로 공개되지 않는다. 따라서 논문의 비교 실험을 완전히 재현하려면 공개 코드 또는 별도 설정값 확인이 필요하다.

## 평가 지표와 계산식

### 누적수익률

시뮬레이션 전체 기간 동안 포트폴리오 가치가 얼마나 변했는지를 측정한다.

[
CR =
\frac{V_{\mathrm{end}}-V_{\mathrm{start}}}
{V_{\mathrm{start}}}
\times 100
]

* (V_{\mathrm{start}}): 초기 포트폴리오 가치
* (V_{\mathrm{end}}): 종료 시점 포트폴리오 가치

### 연환산수익률

전체 수익률을 연 단위 성장률로 환산한다.

[
AR =
\left[
\left(
\frac{V_{\mathrm{end}}}{V_{\mathrm{start}}}
\right)^{1/N}
-1
\right]
\times 100
]

* (N): 시뮬레이션 기간을 연 단위로 표현한 값

### 샤프지수

무위험수익률을 초과한 수익을 포트폴리오 변동성으로 나눈다.

[
SR =
\frac{\bar{R}-R_f}{\sigma}
]

* (\bar{R}): 평균 포트폴리오 수익률
* (R_f): 무위험수익률
* (\sigma): 포트폴리오 수익률 표준편차

논문은 무위험수익률의 예로 3개월 만기 미국 국채 수익률을 제시한다. 다만 일별·월별 중 어떤 주기의 수익률을 사용했는지, (\sqrt{252})와 같은 연환산 계수를 적용했는지는 밝히지 않는다.

### 최대낙폭

포트폴리오가 이전 고점에서 이후 저점까지 가장 크게 하락한 비율이다.

[
MDD =
\max_{t \in [0,T]}
\left(
\frac{\mathrm{Peak}_t-\mathrm{Trough}_t}
{\mathrm{Peak}_t}
\right)
\times 100
]

이 네 식은 논문 부록에서 직접 정의한다.

## 실험 결과 해석 시 주의점

논문 결과표에서 TradingAgents는 다음 성과를 보고한다. 

| 종목    |     CR | AR/ARR |   SR |   MDD |
| ----- | -----: | -----: | ---: | ----: |
| AAPL  | 26.62% | 30.50% | 8.21 | 0.91% |
| GOOGL | 24.36% | 27.58% | 6.39 | 1.69% |
| AMZN  | 23.21% | 24.90% | 5.60 | 2.11% |

그러나 이 결과에는 다음 검증 문제가 남아 있다.

1. **연환산수익률 재현 문제**
   논문이 제시한 약 3개월 기간과 AR 수식을 그대로 적용했을 때, 표의 30.50%·27.58%·24.90%가 어떤 방식으로 산출됐는지 명확하지 않다. 사용한 (N) 또는 별도 연환산 방식이 공개돼야 한다. ([arXiv][1])

2. **샤프지수 계산 주기 미공개**
   평균수익률과 표준편차가 일별인지 전체 거래별인지, 무위험수익률의 주기를 어떻게 맞췄는지 설명되지 않는다. 저자도 높은 샤프지수가 이례적이라고 인정한다. ([arXiv][1])

3. **MDD 설명과 표의 불일치**
   본문은 TradingAgents의 MDD가 2를 넘지 않는다고 서술하지만, 결과표의 AMZN MDD는 2.11%다. ([arXiv][1])

4. **거래비용과 체결 모델 미공개**
   실험 설정에는 매수·매도·보유 신호를 실행한다고 설명돼 있지만, 수수료, 세금, 스프레드, 슬리피지, 주문 지연, 부분체결과 시장충격의 구체적인 수치가 제시되지 않는다. ([arXiv][1])

5. **구성요소별 효과 검증 부족**
   Bull/Bear 토론 제거, 위험관리팀 제거, 단일 에이전트 전환, 구조화 보고서 제거와 같은 절제 실험이 제시되지 않는다. 따라서 초과성과가 멀티 에이전트 토론에서 발생했는지, 특정 프롬프트·모델·데이터에서 발생했는지 분리하기 어렵다.

6. **반성 에이전트 정의 부족**
   토론과 결론 부분에서는 `reflective agent`를 중요한 구성요소로 언급하지만, 역할 정의와 워크플로 절에서는 반성 에이전트의 입력·출력·갱신 규칙을 별도로 설명하지 않는다. ([arXiv][1])
