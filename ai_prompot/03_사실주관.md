## 한눈에 보기

이 논문은 뉴스 전체를 하나의 LLM에 넣어 매수·매도를 결정하게 하지 않는다. 뉴스 안의 내용을 **검증 가능한 사실**과 **시장 참여자의 의견·전망·감정 같은 주관적 정보**로 분리한 뒤, 두 종류의 정보를 각각 별도 에이전트가 요약하고 추론하게 한다.

최종 트레이더는 다음 정보를 함께 받는다.

1. 가격과 온체인 통계
2. 사실 뉴스 분석
3. 사실 기반 추론
4. 주관 뉴스 분석
5. 주관 기반 추론
6. 과거 매매 결과를 검토한 반성 결과

핵심 아이디어는 **사실과 주관 중 하나를 항상 신뢰하는 것이 아니라, 최근 시장에서 어느 쪽 정보가 실제 수익에 더 도움이 됐는지를 반성 에이전트가 평가하고 다음 판단의 비중을 조절하는 것**이다.

논문의 실험에서는 강세장에서 주관적 심리 정보가 상대적으로 중요했고, 약세장에서는 사실 및 온체인 통계가 손실을 줄이는 데 더 중요한 것으로 나타났다. ([arXiv][2])

## 해결하려는 문제

논문은 “더 강한 LLM이 항상 더 높은 트레이딩 성과를 낸다”는 가정에 의문을 제기한다.

GPT-4o나 o1-mini처럼 추론 능력이 강한 모델은 수학이나 코딩에서는 사실과 논리를 우선하는 특성이 유리하다. 그러나 암호화폐 시장은 사실만으로 움직이지 않고 기대, 공포, 과열, 루머, 전문가 전망 등 심리적 요인에 의해 내재가치에서 크게 이탈할 수 있다.

논문은 기존 LLM 트레이딩에서 다음 문제가 발생한다고 본다.

1. 사실과 의견이 섞인 뉴스 전체를 한 번에 추론한다.
2. 강한 LLM일수록 객관적 사실을 과도하게 우선할 수 있다.
3. 심리가 가격을 주도하는 시장에서는 이러한 사실 편향이 오히려 수익을 낮출 수 있다.
4. 과거에 어떤 정보가 효과적이었는지 다음 의사결정에 체계적으로 반영하지 못한다.

FS-ReasoningAgent는 뉴스 분리, 분리된 추론, 연속형 포지션 결정, 결과 기반 반성을 결합해 이 문제를 해결한다. ([arXiv][2])

## 사실과 주관의 구분

### 사실 정보

사실 에이전트는 외부에서 검증할 수 있는 사건과 수치를 중심으로 분석한다.

* 규제 발표와 제도 변경
* ETF 승인·신청과 정책 변화
* 블록체인 업그레이드
* 해킹, 장애, 프로토콜 출시
* 대규모 자금 이동
* 기업 투자와 자금조달
* 실제 거래량과 가격 변동
* 네트워크 사용량과 온체인 활동

### 주관 정보

주관 에이전트는 사람의 해석, 전망, 감정과 기대를 중심으로 분석한다.

* 애널리스트의 가격 전망
* 전문가와 인플루언서의 발언
* 시장 낙관론과 비관론
* 루머와 기대
* 투자자의 공포와 탐욕
* 특정 사건에 대한 해석
* 가격 상승·하락 가능성에 관한 의견

### 실제 구현상의 분리 방식

사실과 주관이 사전에 사람이 라벨링된 별도 데이터셋으로 제공되는 것은 아니다. 두 에이전트 모두 같은 뉴스 묶음을 입력받고, 프롬프트를 통해 각각 사실 또는 주관적 내용만 추출하도록 지시받는다.

```text
동일한 뉴스 기사 묶음
  ├─ Fact Agent
  │    └─ 검증 가능한 사건과 수치만 추출
  │
  └─ Subjectivity Agent
       └─ 전망·의견·감정·해석만 추출
```

따라서 이 논문의 사실·주관 분리는 별도의 분류 모델이나 정답 라벨에 의한 분리가 아니라 **LLM 프롬프트 기반 의미 분리**다. 공개 코드에서도 두 에이전트가 같은 `state["news"]`를 입력받으며 역할 지시만 다르게 적용된다.

이 방식은 구현이 간단하지만 다음 위험이 있다.

* 하나의 문장에 사실과 의견이 섞일 수 있다.
* 두 에이전트가 같은 내용을 중복 추출할 수 있다.
* 사실 에이전트가 기사 작성자의 해석을 사실처럼 받아들일 수 있다.
* 주관 에이전트가 실제 사건을 감성 신호로 중복 반영할 수 있다.
* 에이전트별 분리 정확도를 평가하는 정답 데이터가 없다.

## 아키텍처와 의사결정 흐름

```text
시장 통계
  └─ Statistics Agent
       └─ 가격·거래량·온체인 활동 분석
                    │
                    ▼
뉴스 ── Fact Agent ── Fact Reasoning Agent
  │         │                 │
  │         └─ 사실 추출      └─ 통계와 사실을 결합한 객관적 추론
  │
  └─ Subjectivity Agent ── Subjectivity Reasoning Agent
             │                         │
             └─ 의견·심리 추출         └─ 심리와 전망 기반 추론
                                             │
과거 행동·수익률 ── Reflection Agent ────────┤
                                             ▼
                                        Trade Agent
                                             │
                                매수·매도 비율 [-1, 1]
                                             │
                                             ▼
                                     포트폴리오 갱신
                                             │
                                             └─ 다음 반성에 피드백
```

논문상 시스템은 다음 네 단계의 계층적 추론을 수행한다.

1. 원시 데이터를 시장 통계, 사실 뉴스, 주관 뉴스로 나눈다.
2. 사실과 주관을 각각 별도로 요약하고 추론한다.
3. 반성 결과와 양쪽 추론을 사용해 매매 비율을 결정한다.
4. 실제 수익률과 이전 추론을 검토해 다음 의사결정 전략을 조정한다. ([arXiv][3])

## 에이전트별 분석 방법

### Statistics Agent

Statistics Agent는 최근 가격과 온체인 통계를 시간순으로 받아 단기 시장 흐름을 요약한다.

논문과 코드에서 확인되는 주요 입력은 다음과 같다.

| 범주      | 데이터                |
| ------- | ------------------ |
| 가격      | 시가, 종가             |
| 시장 활동   | 거래량, 시가총액          |
| 네트워크 활동 | 고유 주소 수, 총 트랜잭션 수  |
| 네트워크 비용 | 총 가스 사용량, 평균 가스 가격 |
| 처리 안정성  | 성공한 트랜잭션 수         |
| 자금 이동   | 총 전송 가치            |

에이전트는 각 지표의 수치 자체를 예측 모델에 넣어 계산하는 것이 아니라, 최근 여러 날짜의 변화를 자연어로 해석한다.

```text
최근 7일 가격·온체인 데이터
  → 주소와 거래량 증가·감소 확인
  → 가스 가격과 네트워크 수요 확인
  → 가격 방향과 온체인 활동의 일치 여부 확인
  → 상승·하락·혼조 추세를 자연어로 요약
```

공개 코드의 기본 `price_window`는 7이므로 최대 최근 7일 정도의 상태를 프롬프트에 포함한다.

### Fact Agent

Fact Agent는 뉴스에서 구체적인 사건과 객관적 변화를 추출한다.

분석 대상은 다음과 같다.

* 규제와 정책
* 기술 업그레이드
* 자금조달
* 대규모 매매
* 기관의 실제 행동
* 네트워크 장애 또는 해킹
* 가격과 거래량의 실제 변화

Fact Agent의 출력은 하나의 간결한 문단이며, 사실을 나열하는 데서 끝나지 않고 해당 사건이 향후 시장에 미칠 방향까지 추정한다.

### Subjectivity Agent

Subjectivity Agent는 동일한 뉴스에서 전문가 전망, 평가, 기대, 공포와 시장 해석을 추출한다.

예를 들어 다음과 같은 표현이 분석 대상이 된다.

```text
“ETH가 2,000달러까지 하락할 수 있다”
“이번 업그레이드는 시장에서 과소평가되고 있다”
“기관투자자 유입이 다음 상승장을 만들 것이다”
```

이 정보는 사실 여부와 별개로 투자자의 행동을 변화시킬 수 있으므로 단기 가격 변동의 별도 신호로 취급된다.

### Fact Reasoning Agent

Fact Reasoning Agent는 다음 두 출력을 결합한다.

```text
Statistics Agent 보고서
  + Fact Agent 보고서
  → 객관적 매매 논리
```

예를 들어 뉴스에서는 매도 압력이 관찰되지만 온체인 주소와 거래량이 증가했다면, 단기 약세와 장기 네트워크 강도를 분리해 해석한다.

주요 판단 항목은 다음과 같다.

* 사실 뉴스와 온체인 데이터의 방향이 일치하는가
* 단기 가격 압력과 장기 펀더멘털이 다른가
* 기술·규제 사건이 실제 수요로 연결될 가능성이 있는가
* 자금 유입 또는 유출이 데이터에서 확인되는가
* 매수·보유·매도 중 어떤 방향이 사실에 더 부합하는가

### Subjectivity Reasoning Agent

Subjectivity Reasoning Agent는 주관 뉴스 요약을 다시 해석해 심리가 가격에 전달되는 경로를 만든다.

```text
전문가 전망·시장 의견
  → 긍정·부정 방향 파악
  → 심리의 강도와 확산 가능성 판단
  → 단기 변동성에 미칠 영향 추정
  → 심리 기반 매매 논리 생성
```

단순 감성분석과 다른 점은 “긍정 단어가 많다”는 결과만 내는 것이 아니라, 해당 의견이 투자자 행동과 가격에 어떤 영향을 줄지를 자연어로 추론한다. ([arXiv][2])

## Reflection Agent

Reflection Agent는 최근 의사결정과 결과를 검토해 다음 매매에서 사실과 주관을 어느 정도 강조해야 하는지 제안한다.

기본적으로 다음 기록을 사용한다.

```text
이전 Trade Agent의 추론
이전 실제 매매 비율
이후 발생한 일별 수익률
```

공개 코드의 기본 `reflection_window`는 3이다. 최근 약 3일의 추론, 행동, 일별 수익률을 프롬프트에 넣고 다음 내용을 평가한다.

* 사실 기반 판단이 실제로 맞았는가
* 주관적 심리 신호가 가격에 먼저 반영됐는가
* 한쪽 정보에 과도하게 의존해 손실이 발생했는가
* 현재 시장에서는 공격적 또는 보수적 접근이 필요한가
* 다음 판단에서 사실과 주관에 어떤 비중을 부여해야 하는가

논문의 출력 예시에서는 사실 60%, 주관 40%처럼 자연어 비중을 제안한다. 하지만 이 비중으로 신호를 수학적으로 가중합하는 것은 아니다. 반성 결과가 Trade Agent의 프롬프트에 들어가고, Trade Agent가 이를 참고해 최종 결정을 생성하는 방식이다. ([arXiv][3])

개념적으로 다음과 같이 표현할 수 있다.

[
w_t^{F}+w_t^{S}=1
]

* (w_t^{F}): 시점 (t)에서 사실 정보에 부여할 권고 비중
* (w_t^{S}): 시점 (t)에서 주관 정보에 부여할 권고 비중

그러나 이 값은 코드에서 강제되는 포트폴리오 계산값이 아니다. 프롬프트는 두 비중의 합을 1로 작성하라고 요구하지만 별도 파서나 검증 로직은 없으며, 실제 환경은 최종 행동값만 추출한다.

## Trade Agent와 연속형 매매 신호

Trade Agent는 최종 행동을 1자리 소수의 연속형 값으로 출력한다.

[
a_t \in [-1,1]
]

|    행동값 | 의미             |
| -----: | -------------- |
| (-1.0) | 보유 코인 전량 매도    |
| (-0.4) | 보유 코인의 40% 매도  |
|  (0.0) | 보유             |
|  (0.3) | 가용 현금의 30%로 매수 |
|  (1.0) | 가용 현금 전액으로 매수  |

따라서 행동값은 미래 가격수익률 예측값이 아니라 **현재 현금 또는 보유 코인 중 얼마를 거래할지 나타내는 주문 비율**이다.

Trade Agent는 다음 네 항목을 출력하도록 지시받는다.

1. 전체 보고서에 관한 종합 추론
2. 사실과 주관의 비중 및 충돌 해결
3. 위험관리 방법
4. 최종 행동값

논문은 이를 통해 단순한 `BUY/SELL/HOLD`보다 확신도와 위험 수준을 포지션 크기에 반영한다고 설명한다. ([arXiv][2])

## 포트폴리오와 주문 계산

공개 코드의 초기 자산은 100만 달러이며, 시작 시 현금과 코인을 50대 50으로 나눈다.

[
W_0=1{,}000{,}000
]

[
C_0=0.5W_0
]

[
H_0=\frac{W_0-C_0}{P_0}
]

* (W_0): 초기 순자산
* (C_0): 초기 현금
* (H_0): 초기 코인 보유량
* (P_0): 시작일 시가

공개 코드에 이 초기화 로직이 직접 구현돼 있다.

### 매수 계산

행동값이 (a_t>0)이면 현재 현금 중 (a_t) 비율을 사용한다.

[
\Delta C_t=a_tC_t
]

[
\Delta H_t=\frac{\Delta C_t}{P_t}
]

[
H_{t}^{\prime}=H_t+\Delta H_t
]

[
C_{t}^{\prime}
==============

C_t-\Delta C_t
-F_{\mathrm{gas},t}
-F_{\mathrm{exchange},t}
]

### 매도 계산

행동값이 (a_t<0)이면 현재 보유 코인 중 (|a_t|) 비율을 매도한다.

[
\Delta H_t=|a_t|H_t
]

[
\Delta C_t=\Delta H_tP_t
]

[
H_{t}^{\prime}=H_t-\Delta H_t
]

[
C_{t}^{\prime}
==============

C_t+\Delta C_t
-F_{\mathrm{gas},t}
-F_{\mathrm{exchange},t}
]

### 거래비용

공개 코드에는 다음 비용이 적용된다.

[
F_{\mathrm{gas}}
================

# 21000 \times 70 \times 10^{-9}

0.00147
]

이를 현재 코인 가격과 곱해 현금 비용으로 차감한다.

[
F_{\mathrm{gas},t}=0.00147P_t
]

거래소 수수료는 거래금액의 0.4%다.

[
F_{\mathrm{exchange},t}
=======================

0.004 \times \Delta C_t
]

공개 구현에는 스프레드, 슬리피지, 시장충격, 호가 잔량과 부분체결 모델이 없다. 모든 거래는 해당 날짜의 시가에서 즉시 전량 체결된 것으로 처리한다.

## 데이터 시점과 체결 순서

시뮬레이션의 하루 흐름은 다음과 같다.

```text
전일 뉴스와 온체인 데이터
  + 당일 시가
  → 에이전트 분석
  → 당일 시가로 거래
  → 다음 날 시가로 포트폴리오 평가
  → 당일 수익률 계산
```

코드 주석에서도 에이전트 상태를 다음과 같이 정의한다.

```text
이전 상태: 전일 뉴스, 당일 시가, 현재 현금과 보유량
행동: 매수·매도·보유
새 상태: 당일 뉴스, 다음 날 시가, 변경된 포트폴리오
```

백테스트 구간은 시작일을 거래일에 포함하고 종료일은 거래하지 않는다. 종료일 시가로 최종 순자산을 평가한다.  ([arXiv][2])

## 순자산과 보상 계산

시점 (t)의 순자산은 다음과 같다.

[
W_t=C_t+H_tP_t
]

전체 투자수익률은 초기 순자산 대비 현재 순자산의 변화다.

[
ROI_t=\frac{W_t}{W_0}-1
]

일별 수익률은 이전 평가 시점 순자산 대비 현재 순자산의 변화다.

[
r_t=\frac{W_t}{W_{t-1}}-1
]

환경이 에이전트에 반환하는 보상은 누적 ROI의 일별 증가분이다.

[
Reward_t=ROI_t-ROI_{t-1}
]

이 보상으로 모델 가중치를 학습시키는 강화학습은 수행하지 않는다. 보상과 수익률은 Reflection Agent가 과거 판단을 자연어로 평가할 때 사용된다.

## 평가 지표와 계산식

### 총수익률

[
Return=
\frac{W_{\mathrm{end}}-W_{\mathrm{start}}}
{W_{\mathrm{start}}}
]

* (W_{\mathrm{start}}): 초기 순자산
* (W_{\mathrm{end}}): 종료일 순자산

### 일별 평균수익률

[
\bar r=
\frac{1}{T}
\sum_{t=1}^{T}r_t
]

### 일별 수익률 표준편차

[
\sigma_r=
\sqrt{
\frac{1}{T}
\sum_{t=1}^{T}(r_t-\bar r)^2
}
]

### 샤프지수

[
Sharpe=
\frac{\bar r-r_f}{\sigma_r}
]

논문은 무위험수익률을 0으로 설정한다.

[
r_f=0
]

따라서 실제 계산은 다음과 같다.

[
Sharpe=\frac{\bar r}{\sigma_r}
]

공개 코드는 일별 수익률에 100을 곱한 후 NumPy의 평균과 표준편차를 계산한다. 평균과 표준편차에 동일한 배율이 적용되므로 샤프지수 비율에는 영향을 주지 않는다. 연환산을 위한 (\sqrt{365}) 또는 (\sqrt{252}) 계수는 적용하지 않는다. ([arXiv][2])

> 결과표의 `일별 수익률 평균 ± 표준편차`는 반복 실험의 신뢰구간이 아니다. 백테스트 기간에 발생한 일별 수익률 분포의 평균과 표준편차다.

## 비교 모델과 기준 전략

### LLM 백본

FS-ReasoningAgent와 CryptoTrade에 다음 모델을 각각 적용한다.

* GPT-3.5-turbo
* GPT-4
* GPT-4o
* o1-mini

각 에이전트가 서로 다른 모델을 사용하는 구조가 아니라, 한 번의 실험에서는 Statistics Agent부터 Trade Agent까지 동일한 백본 모델을 사용한다. 공개 코드도 명령행에서 하나의 `--model`을 받아 모든 에이전트 호출에 사용한다.

### Buy and Hold

시작 시 자산을 매수하고 종료일까지 보유한다.

### SMA

가격과 단순이동평균을 비교해 매매한다. 이동평균 기간 후보를 검증 데이터에서 비교하고 가장 좋은 값을 선택한다.

### SLMA

단기·장기 이동평균의 교차를 사용한다. 단기와 장기 기간 조합은 검증 데이터에서 최적화한다.

### MACD

다음 표준 설정을 사용한다.

[
MACD_t=EMA_{12,t}-EMA_{26,t}
]

[
Signal_t=EMA_9(MACD_t)
]

### Bollinger Bands

20일 단순이동평균과 표준편차를 사용한다.

[
Upper_t=SMA_{20,t}+2\sigma_{20,t}
]

[
Lower_t=SMA_{20,t}-2\sigma_{20,t}
]

### CryptoTrade

뉴스와 시장 데이터를 입력받아 LLM이 직접 거래하는 기존 암호화폐 트레이딩 에이전트다. FS-ReasoningAgent는 CryptoTrade와 달리 사실과 주관의 추출·추론을 분리한다. ([arXiv][2])

## 에이전트 제거 실험

논문은 BTC에 o1-mini를 적용하고 에이전트를 하나씩 제거하는 절제 실험을 수행한다.

| 구성                              | 강세 수익률 |  약세 수익률 | 강세 Sharpe | 약세 Sharpe |
| ------------------------------- | -----: | ------: | --------: | --------: |
| 전체 모델                           | 76.19% | -15.91% |      0.46 |     -0.35 |
| Reflection Agent 제거             | 71.77% | -17.85% |      0.44 |     -0.40 |
| Fact Reasoning Agent 제거         | 72.23% | -19.21% |      0.43 |     -0.39 |
| Subjectivity Reasoning Agent 제거 | 66.04% | -16.83% |      0.42 |     -0.36 |
| Statistics Agent 제거             | 74.25% | -20.40% |      0.45 |     -0.36 |

### 강세장 해석

강세장에서 Subjectivity Reasoning Agent를 제거하면 수익률이 76.19%에서 66.04%로 약 10.15%포인트 하락한다.

이는 강세장에서는 다음 요소가 가격 상승을 강화할 수 있다는 해석으로 이어진다.

* 투자자의 낙관적 기대
* 전문가의 상승 전망
* 뉴스에 대한 긍정적 반응
* 사실이 확인되기 전에 형성되는 기대감
* 군중 심리와 추격매수

### 약세장 해석

약세장에서 Statistics Agent를 제거하면 수익률이 -15.91%에서 -20.40%로 악화된다. Fact Reasoning Agent를 제거해도 -19.21%로 손실이 확대된다.

이는 약세장에서 공포와 비관적 의견에 따라 행동하기보다 객관적 가격·온체인 데이터와 실제 사건에 의존하는 것이 손실 통제에 유리할 수 있음을 보여준다. ([arXiv][2])

## 논문과 공개 코드의 차이 및 검증 포인트

### 1. Trade Agent 프롬프트 연결 오류 가능성

공개 코드에서는 Trade Agent 템플릿에 중괄호가 세 개만 존재한다.

```text
ON-CHAIN REPORT: {}
NEWS REPORT: {}
REFLECTION REPORT: {}
```

그러나 실제 `.format()` 호출에는 다음 여섯 값을 전달한다.

```text
온체인 분석
사실 뉴스 분석
주관 뉴스 분석
사실 추론
주관 추론
반성 결과
```

Python은 남는 인자를 무시하므로 현재 코드대로라면 템플릿에 들어가는 값은 앞의 세 개뿐이다.

```text
ON-CHAIN REPORT     ← 온체인 분석
NEWS REPORT         ← 사실 뉴스 분석
REFLECTION REPORT   ← 주관 뉴스 분석
```

따라서 Fact Reasoning Agent, Subjectivity Reasoning Agent와 실제 Reflection Agent의 출력이 최종 Trade Agent에 전달되지 않을 가능성이 높다. 이는 논문 아키텍처와 공개 코드 사이의 중요한 불일치다.

올바른 구현은 다음과 같이 각 보고서를 명시적으로 연결해야 한다.

```python
trader_prompt = template.format(
    statistics_report=statistics_report,
    factual_news_report=factual_news_report,
    subjective_news_report=subjective_news_report,
    factual_reasoning=factual_reasoning,
    subjective_reasoning=subjective_reasoning,
    reflection_report=reflection_report,
)
```

### 2. 기술지표가 사실상 비활성화됨

환경은 SMA, MACD와 Bollinger Bands를 계산하지만, 상태에 넣는 `technical` 딕셔너리에서는 해당 신호들이 주석 처리돼 있다.

따라서 `--use_tech 1`이 기본값이어도 실제 Statistics Agent 프롬프트에 기술지표가 포함되지 않는다. 공개 구현의 Statistics Agent는 사실상 가격과 온체인 통계 중심이다.

### 3. 에이전트 제거 옵션이 직접 구현돼 있지 않음

`use_news`, `use_reflection` 등의 인자가 정의돼 있지만 현재 실행 경로에서는 Fact Agent, Subjectivity Agent와 Reflection Agent를 항상 호출한다.

따라서 논문의 절제 실험을 재현하려면 단순히 인자를 0으로 설정하는 것만으로는 부족하고, 해당 에이전트 호출과 Trade Agent 입력을 코드에서 직접 제거하거나 대체해야 한다.

### 4. 두 종류의 Reflection이 혼재함

코드에는 서로 다른 반성 메커니즘이 존재한다.

* 매일 최근 행동과 일별 수익률을 검토하는 Reflection Agent
* 전체 실험이 실패했을 때 다음 trial용 계획을 생성하는 `update_memory`

후자는 총수익률이 10%를 넘지 못하면 실패로 판단하고 GPT-3.5-turbo로 새 계획을 만든다. 그러나 생성된 메모리를 저장하는 변수와 실제 일별 프롬프트 연결이 불명확해, 교차 trial 메모리가 정상적으로 사용되는지 별도 검증이 필요하다.

### 5. 거래비용 이후 현금 음수 가능성

행동값이 `1.0`이면 가용 현금 전액을 매수에 사용한 후 거래 수수료와 가스비를 추가로 차감한다.

[
C_t'=C_t-C_t-F_t=-F_t
]

따라서 현금이 음수가 될 수 있으며, 주문 전에 수수료를 고려해 최대 주문 가능 금액을 제한하는 로직이 필요하다.

### 6. BTC와 SOL에도 동일한 가스비 상수 적용

코드의 가스비 변수는 Ethereum의 가스 한도와 Gwei를 전제로 작성돼 있다. 하지만 같은 환경 클래스를 BTC와 SOL에도 사용한다.

따라서 BTC·SOL 백테스트에서도 Ethereum식 고정 가스비를 적용할 가능성이 있으며, 자산별 네트워크 수수료 모델로 분리해야 한다.

### 7. 실행 환경과 저장소 구성 불일치

논문은 Python 3.12.5, PyTorch 2.0.0과 NVIDIA H100 네 장을 실험 환경으로 기재한다. 그러나 공개 코드는 대부분 OpenAI 원격 API 호출과 Pandas 기반 시뮬레이션이며, 루트 파일 목록에는 의존성 파일과 데이터 폴더가 보이지 않는다.

또한 `base_config.yaml`은 트레이딩 설정이 아니라 ALFWorld 환경 설정을 포함하고 있어 현재 트레이딩 코드와 직접 관련이 없는 잔여 파일로 보인다. 따라서 공개 복제본만으로 논문 결과를 그대로 재현하기는 어렵다. ([arXiv][2])

## 자동매매 설계에 주는 시사점

### 사실과 주관을 데이터 단계부터 분리한다

단일 뉴스 감성 점수만 만들지 말고 다음처럼 별도 필드를 둔다.

```yaml
news_analysis:
  facts:
    - event:
      source:
      published_at:
      effective_at:
      verifiability:
      expected_impact:

  subjectivity:
    - speaker:
      opinion:
      sentiment:
      confidence:
      audience_reach:
      expected_impact:
```

### 두 신호의 성과를 시장 국면별로 추적한다

```yaml
reasoning_performance:
  regime: bull | bear | sideways | high_volatility
  fact_signal_return:
  subjectivity_signal_return:
  fact_hit_rate:
  subjectivity_hit_rate:
  recommended_fact_weight:
  recommended_subjectivity_weight:
```

논문의 강세·약세 결과를 고정 규칙으로 사용하기보다, 실제 운영 데이터에서 각 신호의 최근 예측력과 수익 기여도를 계산해 가중치를 갱신해야 한다.

### 자연어 가중치를 수치로 검증한다

논문 시스템은 Reflection Agent가 자연어로 60대 40과 같은 비중을 제안한다. 실제 시스템에서는 다음과 같이 수치화하는 편이 안전하다.

[
s_t
===

w_t^F s_t^F
+
w_t^S s_t^S
+
w_t^Q s_t^Q
]

* (s_t^F): 사실 기반 신호
* (s_t^S): 주관 기반 신호
* (s_t^Q): 가격·온체인 정량 신호
* (w_t^F,w_t^S,w_t^Q): 검증 데이터로 결정한 가중치

[
w_t^F+w_t^S+w_t^Q=1
]

LLM은 가중치 후보와 근거를 제안하되, 실제 주문에는 통계적으로 검증된 범위와 위험 한도를 적용해야 한다.

### Reflection을 사후 설명이 아닌 성과 원장으로 만든다

```yaml
decision_record:
  decision_time:
  action:
  position_before:
  position_after:

  fact_reasoning:
  subjectivity_reasoning:
  quantitative_reasoning:

  predicted_horizon:
  expected_direction:
  invalidation_condition:

  realized_result:
    return_1d:
    return_3d:
    return_7d:
    max_adverse_excursion:
    max_favorable_excursion:

  attribution:
    fact_correct:
    subjectivity_correct:
    quantitative_correct:
    dominant_reason:
```

## 한계와 주의점

* 실험 구간이 자산당 강세·약세 약 1∼2개월로 짧다.
* BTC, ETH, SOL 세 자산만 분석한다.
* 강세장과 약세장을 사후에 선택한 구간이므로 시장 국면 선택 편향이 있을 수 있다.
* 여러 LLM 중 시장별 최고 모델을 선택하면 실제 사전 배치 성과보다 좋아 보일 수 있다.
* 사실·주관 분리의 정확도를 평가하는 라벨 데이터나 분류 성능이 없다.
* 일별 뉴스 전체가 길어질 경우 프롬프트 길이와 기사 선택 편향 문제가 발생한다.
* 뉴스 출판시각, 수집시각, 실제 주문시각의 엄격한 정합성 검증이 충분히 공개되지 않았다.
* 샤프지수는 연환산하지 않았고 무위험수익률을 0으로 둔다.
* 최대낙폭, Calmar ratio, Sortino ratio, turnover 등의 위험지표는 제시하지 않는다.
* 주문은 시가에 즉시 체결된다고 가정하며 스프레드와 슬리피지가 없다.
* 0.4% 거래소 수수료와 고정 가스비는 적용하지만 자산별 실제 비용 구조는 반영하지 않는다.
* LLM 출력의 사실·주관 비중은 자연어 권고일 뿐 코드에서 강제되지 않는다.
* 공개 코드의 Trade Agent 연결 구조가 논문의 설명과 다를 가능성이 있다.
* 공개 저장소에 데이터와 완전한 설치 절차가 없어 결과 재현성이 제한된다.

## 핵심 평가

FS-ReasoningAgent의 가장 중요한 기여는 “뉴스 감성을 추가했다”는 점이 아니다. **동일한 뉴스 안에서도 검증 가능한 사건과 시장 참여자의 믿음을 별도의 추론 경로로 처리하고, 과거 성과를 통해 두 경로의 상대적 중요도를 조정한다는 것**이다.

다만 논문의 구조적 아이디어와 공개 코드 구현 사이에는 차이가 있으며, 특히 최종 Trade Agent에 각 추론과 Reflection 결과가 실제로 연결되는지를 먼저 수정·검증해야 한다.

실제 시스템에 적용할 때는 FS-ReasoningAgent를 주문 엔진으로 그대로 사용하는 것보다 다음 역할의 **리서치 어댑터**로 사용하는 편이 적절하다.

```text
뉴스 사실 추출
  + 주관적 시장 심리 추출
  + 온체인·가격 분석
  + 시장 국면별 신호 기여도 평가
  → 구조화된 투자 근거 생성
  → 별도 정량 리스크 엔진
  → 주문 크기와 체결 방식 결정
```
