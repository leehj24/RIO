# 한눈에 보기

일반적인 자기회귀 언어모델은 다음 토큰을 하나씩 순차적으로 생성한다.

```text
prefix
  → 큰 모델 1회
  → token 1
  → 큰 모델 1회
  → token 2
  → 큰 모델 1회
  → token 3
  → ...
```

\(K\)개의 토큰을 생성하려면 목표모델을 최소 \(K\)번 직렬 실행해야 한다.

추측 디코딩은 빠른 초안모델이 앞으로 나올 토큰 여러 개를 먼저 제안하고, 큰 목표모델이 이 제안들을 병렬로 검증하게 한다.

```text
빠른 초안모델 Mq
  → x1, x2, ..., xγ 제안

큰 목표모델 Mp
  → 모든 초안 위치의 확률을 한 번에 계산
  → 앞에서부터 수락·거절
  → 처음 거절된 위치는 보정분포로 다시 샘플링
```

한 번의 목표모델 검증으로 다음 수의 토큰을 생성한다.

```text
최악:
1개

일부 초안 수락:
2개~γ개

모든 초안 수락:
γ+1개
```

이 방법의 핵심은 작은 모델이 낸 답을 그대로 믿는 것이 아니다. 초안 토큰을 확률적으로 수락하고, 거절된 지점에서는 정확한 보정분포를 사용한다.

따라서 최종 출력은 다음을 만족한다.

\[
x_t\sim p(x_t\mid x_{<t})
\]

즉, 목표모델을 일반적인 자기회귀 방식으로 실행했을 때와 **동일한 출력 확률분포**를 갖는다.

이 특성 때문에 추측 디코딩은 다음 기법과 구분된다.

| 기법 | 속도 향상 | 목표모델 출력분포 보존 | 모델 재학습 |
| --- | --- | --- | --- |
| 작은 모델로 교체 | 가능 | 아니오 | 선택적 |
| 지식 증류 모델 사용 | 가능 | 아니오 | 필요 |
| 양자화 | 가능 | 일반적으로 완전 동일하지 않음 | 보통 불필요 |
| Early Exit | 가능 | 일반적으로 동일하지 않음 | 구조에 따라 필요 |
| 추측 디코딩 | 가능 | **정확히 동일** | **불필요** |

# 왜 자동매매·멀티 에이전트 자료에 필요한가

LLM 기반 트레이딩 시스템은 다음과 같이 여러 번의 생성 호출을 수행할 수 있다.

```text
뉴스 분석가
  → 펀더멘털 분석가
  → 기술 분석가
  → 강세 연구원
  → 약세 연구원
  → 리스크 관리자
  → 최종 트레이더
```

한 에이전트의 출력이 500토큰이고 8개 에이전트가 순차적으로 실행되면 총 생성토큰은 약 4,000개가 된다.

일반 자기회귀 디코딩에서는 각 토큰마다 큰 모델의 디코딩 단계가 필요하다.

추측 디코딩으로 평균 2~3개의 토큰을 한 목표모델 단계에서 확정할 수 있다면, 모델 생성 구간의 지연시간을 크게 줄일 수 있다.

다만 다음 지연은 줄이지 않는다.

- 뉴스 API 응답
- 검색엔진·RAG 검색
- 데이터베이스 조회
- Python 도구 실행
- 가격 데이터 수집
- 에이전트 간 직렬 의존
- 브로커 주문 전송
- 거래소 체결 지연

따라서 전체 처리시간은 다음처럼 나눠야 한다.

\[
T_{\text{total}}
=
T_{\text{data}}
+
T_{\text{retrieval}}
+
T_{\text{tools}}
+
T_{\text{LLM-prefill}}
+
T_{\text{LLM-decode}}
+
T_{\text{risk}}
+
T_{\text{broker}}
\]

추측 디코딩이 직접 줄이는 것은 주로 다음 항목이다.

\[
T_{\text{LLM-decode}}
\]

# 기존 디코딩의 병목

## 자기회귀 직렬성

목표모델 \(M_p\)가 다음 토큰분포를 생성한다고 하자.

\[
p(x_t\mid x_{<t})
=
M_p(x_{<t})
\]

한 토큰을 생성한 뒤에야 다음 토큰의 입력을 알 수 있다.

\[
x_1
\rightarrow
x_2
\rightarrow
x_3
\rightarrow
\cdots
\rightarrow
x_K
\]

따라서 \(K\)개 토큰을 생성하는 critical path는 \(K\)번의 직렬 목표모델 실행으로 구성된다.

## 메모리 대역폭 병목

대형 Transformer의 배치 크기 1 디코딩은 연산장치의 전체 산술성능을 항상 사용하지 못할 수 있다.

각 디코딩 단계마다 다음 데이터를 읽어야 한다.

- 모델 가중치
- KV cache
- 현재 토큰의 hidden state

이 때문에 단일 토큰을 처리하는 시간이 순수 FLOP 수보다 메모리 접근과 장치 간 통신에 더 크게 제한될 수 있다.

추측 디코딩은 목표모델이 여러 초안 위치를 동시에 계산하도록 만들어 남아 있는 병렬연산 자원을 사용한다.

```text
기존:
큰 모델을 1토큰씩 여러 번 호출

추측:
큰 모델이 여러 위치를 병렬 검증
```

중요한 점은 총 산술연산량이 반드시 줄어드는 것이 아니라는 사실이다.

```text
wall-clock latency:
감소 가능

총 FLOPs:
증가 가능
```

# 기호 정의

| 기호 | 의미 |
| --- | --- |
| \(M_p\) | 최종 출력을 정의하는 큰 목표모델 |
| \(M_q\) | 초안 토큰을 제안하는 빠른 근사모델 |
| \(p(x)\) | 현재 prefix에서 목표모델의 다음 토큰분포 |
| \(q(x)\) | 현재 prefix에서 초안모델의 다음 토큰분포 |
| \(\gamma\) | 한 번에 제안하는 초안 토큰 수 |
| \(\beta\) | 특정 prefix에서 초안 토큰의 수락확률 |
| \(\alpha\) | 여러 prefix에 걸친 평균 수락률 \(E[\beta]\) |
| \(c\) | 초안모델 한 단계 walltime / 목표모델 한 단계 walltime |
| \(\hat c\) | 초안모델 한 단계 연산량 / 목표모델 한 단계 연산량 |

논문의 `approximation model`은 현재 문헌에서 흔히 `draft model` 또는 `drafter`라고 부른다.

# 표준화된 샘플링

논문은 다음 디코딩 방법을 모두 조정된 확률분포에서의 표준 샘플링으로 표현한다.

- argmax
- temperature sampling
- top-k
- nucleus sampling
- 기타 logits 필터링

예를 들어 greedy decoding은 가장 높은 확률의 토큰만 남기고 나머지를 0으로 만든 분포에서 샘플링하는 것과 같다.

\[
p_{\mathrm{greedy}}(x)
=
\begin{cases}
1, & x=\arg\max_z p(z)\\
0, & \text{otherwise}
\end{cases}
\]

따라서 이후의 \(p(x)\)는 softmax 원분포일 수도 있고, temperature·top-k·top-p 처리가 끝난 **최종 목표 샘플링 분포**일 수도 있다.

추측 샘플링의 정확성은 이 최종 \(p(x)\)를 보존한다.

# 단일 토큰의 추측 샘플링

## 1. 초안 토큰 제안

초안모델에서 토큰을 하나 뽑는다.

\[
x\sim q(x)
\]

## 2. 수락확률

제안된 토큰 \(x\)를 다음 확률로 수락한다.

\[
a(x)
=
\min
\left(
1,
\frac{p(x)}{q(x)}
\right)
\]

균등난수 \(r\sim U(0,1)\)를 사용하면 다음과 같다.

\[
r\leq
\min
\left(
1,
\frac{p(x)}{q(x)}
\right)
\]

이면 수락한다.

### 경우 1: \(q(x)\leq p(x)\)

\[
\frac{p(x)}{q(x)}
\geq1
\]

따라서 항상 수락한다.

초안모델이 해당 토큰의 확률을 목표모델보다 낮게 보았다면 초안이 그 토큰을 과도하게 생성한 것이 아니므로 그대로 사용할 수 있다.

### 경우 2: \(q(x)>p(x)\)

\[
a(x)
=
\frac{p(x)}{q(x)}
\]

초안모델이 해당 토큰을 목표모델보다 과도하게 자주 제안하므로 일부를 거절해야 한다.

## 3. 거절 시 보정분포

토큰이 거절되면 다음 분포에서 새 토큰을 샘플링한다.

\[
p'(x)
=
\operatorname{norm}
\left(
\max(0,p(x)-q(x))
\right)
\]

정규화까지 풀어 쓰면 다음과 같다.

\[
p'(x)
=
\frac{
[p(x)-q(x)]_+
}{
\sum_z[p(z)-q(z)]_+
}
\]

여기서

\[
[u]_+
=
\max(0,u)
\]

이다.

이 분포는 초안모델이 목표모델보다 부족하게 할당한 확률질량만 모은 것이다.

# 왜 출력분포가 정확히 \(p\)가 되는가

특정 토큰 \(x\)가 최종 결과가 될 확률을 생각한다.

## 수락 경로의 확률

초안이 \(x\)를 제안할 확률은 \(q(x)\)다.

제안을 수락할 확률은 다음과 같다.

\[
\min
\left(
1,
\frac{p(x)}{q(x)}
\right)
\]

따라서 수락 경로로 \(x\)가 출력될 확률은 다음과 같다.

\[
q(x)
\min
\left(
1,
\frac{p(x)}{q(x)}
\right)
=
\min(p(x),q(x))
\]

## 거절 경로의 확률

전체 거절확률은 다음과 같다.

\[
P(\mathrm{reject})
=
1-\sum_z\min(p(z),q(z))
\]

두 분포의 총합이 모두 1이므로 다음 관계가 성립한다.

\[
1-\sum_z\min(p(z),q(z))
=
\sum_z[p(z)-q(z)]_+
\]

거절 뒤 보정분포에서 \(x\)를 선택할 확률을 곱하면 다음과 같다.

\[
P(\mathrm{reject})p'(x)
=
[p(x)-q(x)]_+
\]

## 두 경로의 합

\[
P(\mathrm{output}=x)
=
\min(p(x),q(x))
+
[p(x)-q(x)]_+
\]

항상 다음과 같다.

\[
\min(p(x),q(x))
+
[p(x)-q(x)]_+
=
p(x)
\]

따라서 최종 출력분포는 정확히 다음과 같다.

\[
x\sim p(x)
\]

즉, 초안모델의 정확도가 낮아도 **출력분포의 정확성은 깨지지 않는다**. 낮은 정확도는 수락률과 속도만 악화시킨다.

# 여러 토큰을 처리하는 추측 디코딩

초안 길이를 \(\gamma\)라고 하자.

## 1. 초안모델의 자기회귀 제안

\[
q_1(x)
=
M_q(\mathrm{prefix})
\]

\[
x_1\sim q_1
\]

\[
q_2(x)
=
M_q(\mathrm{prefix}+x_1)
\]

\[
x_2\sim q_2
\]

이를 \(\gamma\)번 반복한다.

\[
x_1,x_2,\ldots,x_\gamma
\]

초안모델 자체는 기본 논문에서 자기회귀적으로 실행되므로 초안 단계에는 \(\gamma\)번의 작은 모델 실행이 필요하다.

## 2. 목표모델의 병렬 검증

목표모델은 다음 분포들을 한 번의 병렬 실행으로 계산한다.

\[
p_1(x)
=
M_p(\mathrm{prefix})
\]

\[
p_2(x)
=
M_p(\mathrm{prefix}+x_1)
\]

\[
\cdots
\]

\[
p_{\gamma+1}(x)
=
M_p(\mathrm{prefix}+x_1+\cdots+x_\gamma)
\]

실제 Transformer 구현에서는 초안 토큰 전체를 하나의 sequence block으로 넣고 causal mask를 사용해 각 위치의 logits를 동시에 얻을 수 있다.

## 3. 왼쪽에서부터 순차 수락

각 초안 토큰 \(x_i\)에 대해 다음을 검사한다.

\[
r_i
\leq
\min
\left(
1,
\frac{p_i(x_i)}{q_i(x_i)}
\right)
\]

앞에서부터 연속으로 수락한다.

```text
x1 accepted
x2 accepted
x3 rejected
x4 이후는 폐기
```

처음 거절된 위치 뒤의 초안은 prefix가 달라지므로 사용할 수 없다.

## 4. 보정 토큰 추가

처음 거절된 위치가 \(n+1\)이면 다음 보정분포를 만든다.

\[
p'(x)
=
\operatorname{norm}
\left(
\max
\left(
0,
p_{n+1}(x)-q_{n+1}(x)
\right)
\right)
\]

여기서 토큰 \(t\)를 하나 샘플링한다.

\[
t\sim p'
\]

최종 출력은 다음과 같다.

\[
x_1,\ldots,x_n,t
\]

## 5. 모든 초안이 수락된 경우

\[
n=\gamma
\]

이면 목표모델이 이미 계산한 다음 분포에서 한 토큰을 추가로 뽑는다.

\[
t\sim p_{\gamma+1}
\]

최종적으로 다음을 생성한다.

\[
x_1,\ldots,x_\gamma,t
\]

따라서 한 번의 목표모델 검증으로 최대 다음 수의 토큰을 얻는다.

\[
\gamma+1
\]

# 알고리즘 의사코드

```python
def speculative_decoding_step(
    target_model,
    draft_model,
    prefix,
    gamma,
):
    draft_tokens = []
    draft_distributions = []

    # 1. Draft model generates γ guesses autoregressively.
    current = prefix

    for _ in range(gamma):
        q = draft_model.next_token_distribution(current)
        x = sample(q)

        draft_distributions.append(q)
        draft_tokens.append(x)
        current = current + [x]

    # 2. Target model scores all speculative prefixes in parallel.
    target_distributions = target_model.score_draft_sequence(
        prefix=prefix,
        draft_tokens=draft_tokens,
    )
    # p_1, ..., p_(γ+1)

    accepted = []

    # 3. Accept guesses until the first rejection.
    for i, x in enumerate(draft_tokens):
        p = target_distributions[i]
        q = draft_distributions[i]

        q_x = q[x]
        p_x = p[x]

        acceptance_probability = min(
            1.0,
            p_x / q_x,
        )

        if random_uniform() <= acceptance_probability:
            accepted.append(x)
            continue

        # 4. First rejection: sample from correction distribution.
        correction = positive_part(p - q)
        correction = correction / correction.sum()

        replacement = sample(correction)

        return prefix + accepted + [replacement]

    # 5. All draft tokens accepted: generate one extra target token.
    extra = sample(target_distributions[gamma])

    return prefix + accepted + [extra]
```

실제 구현에서는 다음 예외처리가 필요하다.

- \(q(x)=0\)
- top-k·top-p 이후 빈 분포
- EOS 토큰
- 초안 중간에서 EOS가 등장한 경우
- vocabulary·tokenizer 불일치
- floating-point 음수와 정규화 오차
- batch별 서로 다른 수락 길이
- KV cache rollback

# 수락률

특정 prefix에서의 수락확률을 \(\beta\)라고 한다.

\[
\beta
=
E_{x\sim q}
\left[
\min
\left(
1,
\frac{p(x)}{q(x)}
\right)
\right]
\]

이를 전개하면 다음과 같다.

\[
\beta
=
\sum_x
q(x)
\min
\left(
1,
\frac{p(x)}{q(x)}
\right)
\]

\[
\beta
=
\sum_x\min(p(x),q(x))
\]

## 논문의 \(D_{LK}\)

논문은 다음 대칭 divergence를 정의한다.

\[
D_{LK}(p,q)
=
\sum_x
\left|
p(x)-M(x)
\right|
\]

여기서

\[
M(x)
=
\frac{p(x)+q(x)}{2}
\]

이므로 다음과 같다.

\[
D_{LK}(p,q)
=
\frac{1}{2}
\sum_x|p(x)-q(x)|
\]

이는 total variation distance와 같은 형태다.

다음 관계가 성립한다.

\[
D_{LK}(p,q)
=
1-\sum_x\min(p(x),q(x))
\]

따라서

\[
\beta
=
1-D_{LK}(p,q)
\]

여러 prefix에서의 평균 수락률을 \(\alpha\)라고 하면 다음과 같다.

\[
\alpha
=
E[\beta]
\]

\[
\alpha
=
1-E[D_{LK}(p,q)]
\]

즉, 목표분포와 초안분포가 가까울수록 \(\alpha\)가 높다.

# 한 번에 생성되는 예상 토큰 수

각 초안 토큰이 독립적으로 평균 확률 \(\alpha\)로 수락된다는 단순화된 가정을 사용한다.

한 번의 알고리즘 반복이 생성하는 토큰 수의 기대값은 다음과 같다.

\[
E[N]
=
1+\alpha+\alpha^2+\cdots+\alpha^\gamma
\]

등비수열을 정리하면 다음과 같다.

\[
E[N]
=
\frac{
1-\alpha^{\gamma+1}
}{
1-\alpha
}
\tag{1}
\]

\(\alpha=1\)일 때는 극한으로 다음과 같다.

\[
E[N]=\gamma+1
\]

## 예시 1

\[
\alpha=0.8,
\qquad
\gamma=5
\]

\[
E[N]
=
\frac{
1-0.8^6
}{
1-0.8
}
\]

\[
E[N]
=
3.68928
\]

초안모델 비용을 무시하면 목표모델 한 번당 평균 약 3.69개 토큰을 생성한다.

## 예시 2

\[
\alpha=0.9,
\qquad
\gamma=10
\]

\[
E[N]
=
\frac{
1-0.9^{11}
}{
0.1
}
\]

\[
E[N]
\approx6.86
\]

최대 11개 중 평균 약 6.86개가 한 번의 목표 검증으로 생성된다.

## 낮은 수락률

\[
\alpha=0.3,
\qquad
\gamma=7
\]

\[
E[N]
=
\frac{
1-0.3^8
}{
0.7
}
\approx1.43
\]

초안 7개를 만들었는데 평균 1.43개만 얻으므로 효율이 낮다.

# Walltime 비용비 \(c\)

초안모델 한 단계와 목표모델 한 단계의 실행시간 비율을 다음과 같이 정의한다.

\[
c
=
\frac{
T_q
}{
T_p
}
\]

- \(T_q\): 초안모델 한 토큰 생성시간
- \(T_p\): 목표모델 한 토큰 생성시간

논문의 실험에서는 초안모델이 목표모델보다 수십~수백 배 작았으며, \(c\)는 대체로 0.05 미만이었다.

실제 \(c\)는 파라미터 수만으로 결정되지 않는다.

- GPU·TPU 종류
- kernel 최적화
- quantization
- batch size
- sequence length
- KV cache 배치
- tensor parallelism
- 모델이 서로 다른 장치에 있는지
- draft-target 간 통신
- 메모리 적재 여부

# 예상 Walltime 가속률

한 반복에서 초안모델은 \(\gamma\)번 실행된다.

\[
\gamma cT_p
\]

목표모델 검증은 병렬 실행이 충분하다는 가정에서 약 한 단계 walltime을 사용한다.

\[
T_p
\]

따라서 한 반복의 예상 walltime은 다음과 같다.

\[
T_{\mathrm{iteration}}
=
(\gamma c+1)T_p
\]

한 반복에서 생성되는 예상 토큰 수는 식 (1)이다.

따라서 일반 디코딩 대비 예상 가속률은 다음과 같다.

\[
S_{\mathrm{wall}}
=
\frac{
1-\alpha^{\gamma+1}
}{
(1-\alpha)(\gamma c+1)
}
\tag{2}
\]

## 예시

\[
\alpha=0.75,
\quad
\gamma=7,
\quad
c=0.02
\]

예상 생성 토큰 수:

\[
E[N]
=
\frac{
1-0.75^8
}{
0.25
}
\approx3.60
\]

초안 비용:

\[
\gamma c+1
=
7(0.02)+1
=
1.14
\]

예상 가속률:

\[
S_{\mathrm{wall}}
=
\frac{3.60}{1.14}
\approx3.16
\]

논문의 EnDe·T5-small·temperature 0 설정에서 이론 예측은 약 3.2배, 실제 측정은 3.4배였다.

# 언제 반드시 이득이 존재하는가

논문은 다음 조건을 제시한다.

\[
\alpha>c
\]

평균 수락률이 초안모델의 상대 walltime 비용보다 높다면, 적절한 \(\gamma\)가 존재하여 속도 향상을 얻을 수 있다.

\(\gamma=1\)일 때의 가속률은 다음과 같다.

\[
S
=
\frac{
1+\alpha
}{
1+c
}
\]

따라서 \(\alpha>c\)이면 다음이 성립한다.

\[
S>1
\]

## 예시

```text
수락률 α:
0.6

초안 비용비 c:
0.02
```

\[
\alpha>c
\]

이므로 최소한 어떤 \(\gamma\)에서는 이득이 가능하다.

반대로 다음 상황에서는 불리할 수 있다.

```text
수락률:
0.1

초안 비용비:
0.3
```

\[
\alpha<c
\]

초안모델이 느린데 목표모델과도 잘 맞지 않는다.

# 총 산술연산량

Walltime이 줄어도 목표모델은 \(\gamma+1\)개 위치를 병렬 계산한다.

초안모델의 연산량 비율을 다음처럼 정의한다.

\[
\hat c
=
\frac{
\mathrm{Ops}(M_q)
}{
\mathrm{Ops}(M_p)
}
\]

일반 디코딩 대비 예상 총 연산량 증가 배수는 다음과 같다.

\[
F_{\mathrm{ops}}
=
\frac{
(1-\alpha)
(\gamma\hat c+\gamma+1)
}{
1-\alpha^{\gamma+1}
}
\tag{3}
\]

## 초안 연산량을 무시한 예시

\[
\hat c=0,
\quad
\alpha=0.8,
\quad
\gamma=5
\]

\[
F_{\mathrm{ops}}
=
\frac{
0.2(6)
}{
1-0.8^6
}
\]

\[
F_{\mathrm{ops}}
\approx1.63
\]

Walltime은 약 3.69배 빨라질 수 있지만 산술연산은 약 1.63배가 된다.

이것이 추측 디코딩의 핵심 trade-off다.

```text
직렬 실행 감소
병렬 연산 증가
```

다음 환경에서 유리하다.

- 배치 크기 1 또는 작음
- latency가 중요함
- 메모리 대역폭 병목
- 병렬연산 여유가 있음

다음 환경에서는 이점이 줄어들 수 있다.

- GPU가 이미 높은 batch로 포화됨
- 총 throughput이 latency보다 중요함
- draft와 target을 동시에 올릴 메모리가 부족함
- 전력·총 연산비가 중요한 환경

# \(\gamma\) 선택

초안 길이를 늘리면 다음 효과가 동시에 발생한다.

## 장점

- 한 번에 더 많은 토큰을 확정할 가능성
- 높은 \(\alpha\)에서 target 호출 횟수 감소

## 단점

- 초안모델 호출 수 증가
- 첫 거절 뒤의 나머지 초안 계산 낭비
- 목표 검증 sequence 길이 증가
- KV cache·메모리 사용 증가
- 낮은 수락률에서 비효율

최적 \(\gamma\)는 다음 식을 최대화하는 정수다.

\[
\gamma^*
=
\arg\max_{\gamma\in\mathbb Z_+}
\frac{
1-\alpha^{\gamma+1}
}{
(1-\alpha)(\gamma c+1)
}
\]

논문은 \(\alpha\)와 \(c\)가 주어지면 작은 정수범위를 순회해 쉽게 찾을 수 있다고 설명한다.

## 실험에서 선택된 값

| 작업 | 초안모델 | Temperature | \(\gamma\) |
| --- | --- | ---: | ---: |
| EnDe | T5-small | 0 | 7 |
| EnDe | T5-base | 0 | 7 |
| EnDe | T5-large | 0 | 7 |
| EnDe | T5-small | 1 | 7 |
| EnDe | T5-base | 1 | 5 |
| EnDe | T5-large | 1 | 3 |
| CNN/DM | T5-small | 0 | 5 |
| CNN/DM | T5-base | 0 | 5 |
| CNN/DM | T5-large | 0 | 3 |
| CNN/DM | T5-small | 1 | 5 |
| CNN/DM | T5-base | 1 | 3 |
| CNN/DM | T5-large | 1 | 3 |

## 동적 \(\gamma\)

실제 수락확률은 모든 토큰에서 같지 않다.

```text
쉬운 구간:
날짜, 문법적 연결어, 고정 표현

어려운 구간:
숫자, 종목명, 새로운 결론, 코드, 계산
```

따라서 최근 수락률을 기반으로 \(\gamma\)를 동적으로 조정할 수 있다.

```python
def choose_gamma(
    recent_acceptance_rate: float,
    draft_cost_ratio: float,
    max_gamma: int = 12,
) -> int:
    best_gamma = 1
    best_speedup = 1.0

    alpha = recent_acceptance_rate
    c = draft_cost_ratio

    for gamma in range(1, max_gamma + 1):
        if alpha == 1.0:
            expected_tokens = gamma + 1
        else:
            expected_tokens = (
                1 - alpha ** (gamma + 1)
            ) / (1 - alpha)

        speedup = expected_tokens / (1 + gamma * c)

        if speedup > best_speedup:
            best_speedup = speedup
            best_gamma = gamma

    return best_gamma
```

논문은 완벽하게 다음 수락길이를 아는 oracle이 있다면, 고정 \(\gamma\)보다 이론적으로 최대 약 60% 추가 향상이 가능하다고 분석한다.

# 초안모델 선택

## 너무 작은 모델

장점:

- \(c\)가 매우 작음
- 메모리 부담이 적음

단점:

- \(p\)와 \(q\)가 달라 \(\alpha\)가 낮을 수 있음

## 너무 큰 모델

장점:

- 목표모델과 분포가 비슷해 \(\alpha\)가 높음

단점:

- 초안 생성비용 \(c\) 증가
- 두 모델을 함께 배포하는 메모리 증가
- 전체 지연시간이 오히려 나빠질 수 있음

논문 실험에서는 목표모델보다 약 두 자릿수 배수, 즉 **대략 두 orders of magnitude 작은 모델**이 수락률과 비용비의 균형이 좋았다.

T5 실험의 파라미터 수는 다음과 같다.

| 모델 | 파라미터 |
| --- | ---: |
| T5-XXL 목표모델 | 11B |
| T5-large | 800M |
| T5-base | 250M |
| T5-small | 77M |

T5-small은 T5-XXL보다 약 다음만큼 작다.

\[
\frac{11{,}000M}{77M}
\approx142.86
\]

약 143배 작은 모델이 가장 높은 실제 가속률을 보였다.

## 이론적으로 가능한 다른 초안모델

논문은 초안모델에 특별한 정확성 제약이 없다고 설명한다. \(q(x)\)를 계산할 수 있으면 보정 샘플링으로 정확한 \(p\)를 복원할 수 있다.

가능한 초안 생성기는 다음과 같다.

- 작은 Transformer
- unigram 모델
- bigram 모델
- context에서 일치 prefix를 찾아 복사하는 모델
- non-autoregressive 모델
- 규칙 기반 휴리스틱
- 이론적으로는 무작위 모델

무작위 초안도 출력분포는 정확하지만 수락률이 매우 낮아 실용적 이득은 작다.

# Tokenizer와 vocabulary 조건

알고리즘은 초안 토큰 \(x_i\)에 대해 목표모델과 초안모델의 확률 \(p_i(x_i)\), \(q_i(x_i)\)를 비교한다.

따라서 기본 형태에서는 두 모델이 동일한 토큰 공간을 공유해야 한다.

```text
같은 tokenizer
같은 vocabulary
같은 token ID 의미
```

서로 다른 tokenizer를 사용하는 모델을 직접 조합하면 다음 문제가 발생한다.

- 초안 토큰을 목표모델 token ID로 대응하기 어려움
- 문자열 단위 경계가 다름
- \(p(x)/q(x)\)를 같은 사건에 대해 계산할 수 없음

후속 연구에는 서로 다른 tokenizer를 다루는 변형이 있지만, 이 논문의 기본 알고리즘과 실험은 같은 모델 계열과 토큰화를 사용한다.

# Greedy decoding과 확률 샘플링

## Temperature 0

목표분포와 초안분포가 각각 argmax token 하나만 남긴 one-hot 분포가 된다.

```text
draft argmax == target argmax:
수락

draft argmax != target argmax:
거절 후 target argmax로 교정
```

따라서 출력 문자열은 일반 greedy decoding과 완전히 동일하다.

## Temperature 1

각 토큰은 확률적으로 샘플링된다.

초안 token이 목표모델의 최고확률 token과 다르더라도 확률비에 따라 수락될 수 있다.

최종 개별 샘플 문자열은 일반 샘플링과 매번 같다는 뜻이 아니다. 보장되는 것은 다음이다.

```text
같은 목표 확률분포
```

동일 random-number stream과 구현 세부사항까지 맞추지 않으면 baseline과 speculative 방식의 한 번의 출력 문자열은 다를 수 있다.

따라서 다음 두 문장을 구분해야 한다.

```text
정확한 표현:
출력 확률분포가 동일하다.

과도한 표현:
어떤 시드에서도 항상 동일한 문자열이 나온다.
```

greedy decoding에서는 문자열 자체가 동일하다.

# 단순 n-gram 초안모델

영어→독일어 번역에서 bigram 모델은 다음 수락률을 보였다.

\[
\alpha\approx0.2
\]

연산비용이 사실상 0이라고 가정하면 \(c\approx0\)이다.

초안 길이가 충분할 때 기대 가속의 상한은 다음과 같다.

\[
\lim_{\gamma\rightarrow\infty}
\frac{
1-\alpha^{\gamma+1}
}{
1-\alpha
}
=
\frac{1}{1-\alpha}
\]

\[
\frac{1}{1-0.2}
=
1.25
\]

따라서 매우 단순한 bigram도 이론적으로 약 1.25배 가속이 가능하다.

이는 초안모델이 반드시 완전한 LLM일 필요는 없음을 보여준다.

# Encoder-Decoder 모델에서의 구조

T5는 encoder-decoder 모델이다.

기본적으로 source 입력은 한 번 인코딩할 수 있다.

```text
목표모델 encoder Mp
초안모델 encoder Mq
```

디코딩 구간에서는 다음이 반복된다.

```text
초안 decoder γ회
  → 목표 decoder 병렬 검증 1회
```

논문의 trace diagram은 다음 세 설정을 비교한다.

```text
Top:
γ=7 speculative decoding

Middle:
γ=3 speculative decoding

Bottom:
standard decoding
```

\(\gamma\)가 커지면 목표 decoder의 직렬 호출 수는 감소하지만 초안 decoder 호출이 늘어난다.

# Decoder-Only LLM 구현

GPT·Llama 계열에서는 encoder가 없다.

```text
Prefill:
prompt 전체의 KV cache 생성

Decode:
초안모델이 γ개 토큰 생성
목표모델이 γ개 토큰 block을 검증
```

목표모델 검증 후 처음 거절된 위치 뒤의 target KV cache는 버리고, 수락된 prefix와 보정토큰까지만 유지해야 한다.

실제 서버에서는 다음 캐시를 관리한다.

```text
target KV cache
draft KV cache
accepted length
rollback position
EOS state
```

# Prefill과 Decode의 구분

추측 디코딩은 긴 입력 prompt의 prefill 비용을 크게 줄이는 기술이 아니다.

```text
긴 문서 50,000토큰 입력
짧은 답변 50토큰
```

이 요청은 prefill이 지배할 수 있으므로 추측 디코딩의 효과가 작다.

반대로 다음 요청은 decode가 지배한다.

```text
입력 1,000토큰
출력 4,000토큰
```

긴 보고서·코드·토론 생성에서는 효과가 커질 수 있다.

전체 가속률은 Amdahl의 법칙처럼 생각할 수 있다.

원래 시간 중 decode 비중을 \(f\), decode 가속률을 \(S_d\)라고 하자.

\[
S_{\mathrm{total}}
=
\frac{
1
}{
(1-f)+f/S_d
}
\]

## 예시 1

decode가 전체의 80%이고 3배 빨라진다.

\[
S_{\mathrm{total}}
=
\frac{
1
}{
0.2+0.8/3
}
\approx2.14
\]

## 예시 2

decode가 전체의 30%뿐이다.

\[
S_{\mathrm{total}}
=
\frac{
1
}{
0.7+0.3/3
}
=
1.25
\]

모델 생성이 3배 빨라져도 전체 시스템은 1.25배에 그칠 수 있다.

# 초안과 목표의 샘플링 설정

이론적으로 \(q\)는 목표분포 \(p\)와 달라도 된다.

정확성을 위해 필요한 것은 다음이다.

1. 목표로 보존하려는 최종분포 \(p\)를 정확히 계산한다.
2. 실제 초안토큰을 생성한 분포 \(q\)를 알고 있다.
3. 수락비율 \(p(x)/q(x)\)를 정확히 계산한다.
4. 거절 시 \([p-q]_+\)에서 보정한다.

따라서 이론적으로 초안모델의 temperature와 목표모델의 temperature가 달라도 \(q\)를 정확히 사용하면 분포보존이 가능하다.

다만 실제 서빙 프레임워크는 구현 단순화와 수락률을 위해 다음을 요구할 수 있다.

- 같은 tokenizer
- 같은 logits processor
- 호환되는 top-k·top-p
- 같은 repetition penalty 처리
- 같은 banned token 목록

sampling processor가 target 검증과 draft 생성에서 불일치하거나, 실제 \(q\)가 아닌 다른 분포를 acceptance ratio에 사용하면 정확성 보장이 깨진다.

## 분포 보존 검증

확률 샘플링에서는 동일 문자열 비율이 아니라 분포를 비교해야 한다.

동일한 prefix를 여러 번 샘플링해 token 빈도를 계산한다.

\[
\hat p_{\mathrm{baseline}}(x)
\]

\[
\hat p_{\mathrm{spec}}(x)
\]

다음 지표를 확인할 수 있다.

\[
TV
=
\frac{1}{2}
\sum_x
\left|
\hat p_{\mathrm{baseline}}(x)
-
\hat p_{\mathrm{spec}}(x)
\right|
\]

또는 카이제곱·KL·Jensen-Shannon divergence를 사용할 수 있다.

유한 표본에서는 완전히 0이 되지 않으므로 신뢰구간이나 permutation test가 필요하다.

# 리스크 관리

추측 디코딩은 출력분포를 보존하므로 금융 의사결정의 위험검증을 생략할 근거가 되지 않는다.

```text
가속된 LLM 출력
  ↓
데이터 시점 확인
  ↓
신호 유효시간 확인
  ↓
포지션 한도
  ↓
손실 한도
  ↓
주문가격·수량 검증
  ↓
실행
```

다음 상황에서는 가속된 답변도 폐기해야 한다.

- 사용한 시장데이터가 오래됨
- 모델 생성 중 가격이 임계치 이상 변경됨
- 뉴스가 취소·수정됨
- LLM 출력이 스키마를 위반함
- 리스크 한도를 초과함
- 주문 예정가격과 현재 호가의 괴리가 큼
- speculative 서버가 fallback 중임

# Fallback 설계

추측 디코딩은 target model의 결과를 정의하므로 draft model이 실패해도 target-only decoding으로 전환할 수 있다.

```python
try:
    output = speculative_generate(
        target=target_model,
        draft=draft_model,
    )
except DraftModelError:
    output = target_model.generate(...)
```

다음 조건에서 자동으로 speculative mode를 끌 수 있다.

```text
최근 수락률 < 임계값
draft latency 증가
GPU memory pressure
high concurrency
짧은 출력 요청
모델·tokenizer 불일치
JSON constraint 오류
```

# 논문의 주요 한계

## 1. Batch size 1 중심

실험은 latency 중심이며 대규모 continuous batching의 처리량을 검증하지 않는다.

## 2. TPU v4·T5 중심 실제 구현

GPT-like·LaMDA는 수락률을 측정했지만 실제 walltime 구현은 T5다.

## 3. i.i.d. 수락 가정

예상 토큰 수와 속도식은 위치별 \(\beta\)가 독립이고 동일한 평균을 가진다고 단순화한다.

실제 언어에서는 수락이 군집적으로 발생할 수 있다.

```text
쉬운 문장구간:
연속 수락

새 개념·숫자:
연속 거절
```

## 4. 추가 연산자원 필요

병렬 검증을 수행할 여유가 없으면 속도 이득이 없다.

## 5. 총 연산량 증가 가능

latency 절감이 비용 절감을 보장하지 않는다.

## 6. 두 모델의 메모리

목표모델과 초안모델을 동시에 올려야 할 수 있다.

## 7. 짧은 생성에서 제한

목표모델을 최소 한 번 실행하므로 출력토큰이 매우 짧으면 startup overhead를 회수하기 어렵다.

## 8. Beam search

논문은 beam search 적용을 향후 과제로 다루며, 일반 확률 샘플링과 같은 완전한 해법으로 제시하지 않는다.

## 9. 서빙 스택 의존

이론적 가속률이 실제 kernel·cache·scheduler에서 그대로 나오지 않는다.

# 논문 부록의 Lenience

기본 알고리즘은 정확한 출력분포를 보존한다.

부록은 정확성을 일부 완화해 수락률을 높이는 `lenience`도 분석한다.

lenience \(l\)을 적용하면 희귀 토큰이 목표확률보다 과도하게 증가하지 않도록 상한을 두면서 더 많은 초안을 수락한다.

이 경우에는 더 이상 목표분포와 완전히 동일하지 않다.

예를 들어 \(l=0.1\)이면 어떤 토큰도 목표확률의 10배를 넘지 않도록 제한하지만, 분포 자체는 달라질 수 있다.

논문의 T5-XXL·EnDe·T5-small 사례에서는 완화가 커질수록 다음처럼 이론 가속률이 증가했다.

| Lenience \(l\) | 최대 확률 왜곡 상한 | \(\alpha\) | 예시 가속 |
| ---: | ---: | ---: | ---: |
| 1.0 | 1× | 0.62 | 2.5× |
| 0.5 | 2× | 0.71 | 3.1× |
| 0.3 | 약 3.3× | 0.76 | 3.6× |
| 0.1 | 10× | 0.84 | 5.0× |

자동매매나 규제 환경에서 `동일 출력분포`가 중요한 경우 lenience를 사용하면 안 된다.

# 다른 가속기법과의 결합

논문은 추측 디코딩이 다음 기법과 배타적이지 않다고 본다.

- quantization
- sparsity
- distillation
- 효율적인 attention
- model parallelism
- KV cache 최적화
- kernel fusion

예를 들어 다음 조합이 가능하다.

```text
quantized target model
  + quantized draft model
  + speculative decoding
  + continuous batching
```

다만 각각이 \(\alpha\), \(c\), 메모리, kernel scheduling에 영향을 주므로 조합별 실측이 필요하다.

# 구현 판단 체크리스트

## 도입하기 좋은 경우

- 로컬 또는 전용 모델서버를 운영함
- target과 호환되는 작은 draft checkpoint가 있음
- 출력이 길음
- batch가 작음
- p95 latency가 중요함
- GPU에 병렬연산 여유가 있음
- target-only fallback이 가능함

## 도입효과가 낮을 수 있는 경우

- 외부 API만 사용해 decoding backend를 제어할 수 없음
- 대부분 요청이 20토큰 이하
- 긴 prompt prefill이 전체 시간을 지배
- GPU가 항상 high batch로 포화
- draft와 target의 도메인 차이가 큼
- tokenizer가 다름
- 모델 메모리가 부족함
- 도구 호출 시간이 LLM보다 김

# 자동매매 적용 권장안

```text
장전·장후:
긴 리서치 보고서
→ speculative decoding 적극 적용

장중 이벤트 분석:
짧은 prompt + 중간 길이 분석
→ p95 latency 기준 부하테스트 후 적용

틱 단위 주문루프:
LLM 자체를 직접 넣지 않음
→ 경량 모델·규칙 실행
→ LLM은 이벤트·전략 재평가에 사용
```

추측 디코딩을 사용해도 수백 마이크로초나 수 밀리초가 필요한 HFT 주문루프를 범용 LLM으로 처리하기는 어렵다.

이 기술은 멀티 에이전트의 수 초 단위 생성지연을 줄이는 데 적합하지, 거래소 matching engine 수준의 latency를 만드는 기술은 아니다.

# 핵심 결론

추측 디코딩의 핵심은 다음 한 문장으로 정리할 수 있다.

```text
작은 모델이 여러 토큰을 먼저 제안하고,
큰 모델이 한 번에 검증하되,
거절 확률질량을 정확히 보정하여
큰 모델의 원래 출력분포를 그대로 유지한다.
```

논문의 가장 중요한 수식은 다음 네 가지다.

## 수락확률

\[
a(x)
=
\min
\left(
1,
\frac{p(x)}{q(x)}
\right)
\]

## 보정분포

\[
p'(x)
=
\operatorname{norm}
\left(
[p(x)-q(x)]_+
\right)
\]

## 예상 생성 토큰 수

\[
E[N]
=
\frac{
1-\alpha^{\gamma+1}
}{
1-\alpha
}
\]

## 예상 walltime 가속률

\[
S_{\mathrm{wall}}
=
\frac{
1-\alpha^{\gamma+1}
}{
(1-\alpha)(\gamma c+1)
}
\]

실험에서는 T5-XXL 11B를 목표모델로 사용해 다음 최대 가속을 측정했다.

- 번역 greedy: 3.4배
- 번역 sampling: 2.6배
- 요약 greedy: 3.1배
- 요약 sampling: 2.3배

그러나 속도는 고정된 보편값이 아니다.

\[
\text{실제 이득}
=
f(
\alpha,
\gamma,
c,
\text{batch},
\text{hardware},
\text{output length},
\text{server implementation}
)
\]

높은 수락률, 낮은 초안비용, 충분한 병렬연산 여유가 함께 있어야 한다.

따라서 자동매매 멀티 에이전트에 적용할 때는 `출력 품질을 바꾸지 않는 2~3배 가속 기술`이라고 단순히 가정하지 말고, 실제 에이전트 프롬프트·모델 조합·동시요청량에서 수락률과 end-to-end latency를 직접 측정해야 한다.
