## 한눈에 보기

이 논문은 LLM에게 실제 주식의 다음 날 등락을 예측시키는 연구가 아니다. 여러 LLM 에이전트를 하나의 인공 주식시장에 투입하고, 각 에이전트가 **시장가·지정가 주문을 제출하며 서로 경쟁하게 만드는 시장 시뮬레이션 프레임워크**를 제안한다.

각 에이전트는 같은 GPT-4o를 사용하더라도 시스템 프롬프트에 따라 가치투자자, 모멘텀 트레이더, 시장조성자, 낙관론자, 비관론자, 역추세 투자자 등 서로 다른 역할을 맡는다. 에이전트는 현재 가격, 호가창, 최근 거래량, 자신의 현금·보유 주식, 배당 정보 등을 읽고 다음 내용을 구조화된 형식으로 출력한다.

- 자신이 계산한 내재가치
- 다음 라운드의 목표가격
- 매수·매도 주문
- 시장가 또는 지정가 여부
- 주문 수량과 지정가격
- 기존 주문의 추가·취소·교체 여부
- 판단 근거

핵심 연구 질문은 다음과 같다.

1. LLM이 자연어 프롬프트로 정의된 투자전략을 일관되게 실행할 수 있는가?
2. LLM은 이익을 극대화하는가, 아니면 프롬프트를 따르는가?
3. 여러 LLM 에이전트가 상호작용하면 가격발견, 버블, 과소반응, 유동성 공급 같은 시장현상이 나타나는가?
4. 유사한 기반모델을 쓰는 에이전트들이 비슷하게 반응해 시장 불안정을 키울 가능성이 있는가?

논문의 결론은 LLM이 지정된 역할은 비교적 일관되게 수행하지만, 반드시 수익을 극대화하지는 않는다는 것이다. 즉, 이 시스템에서 LLM은 효용함수나 보상함수를 최적화하는 강화학습 트레이더가 아니라 **프롬프트에 조건화된 의사결정자**에 더 가깝다.

## 이 논문이 TradingAgents와 다른 점

| 구분 | TradingAgents | Can Large Language Models Trade? |
| --- | --- | --- |
| 핵심 목적 | 한 종목의 매수·매도 판단 생성 | 여러 에이전트가 거래하는 시장 자체를 시뮬레이션 |
| 에이전트 관계 | 한 투자조직 내부의 협업·토론 | 독립된 투자자들이 경쟁하고 거래 |
| 주문 처리 | 최종 투자결정 중심 | 호가창, 시장가·지정가, 부분체결, 주문 취소·교체 |
| 시장 가격 | 외부 실제 시장데이터 | 에이전트 주문과 체결로 내부에서 형성 |
| 주요 평가 | 수익률, 샤프지수, 최대낙폭 | 가격발견, 내재가치 수렴, 유동성, 부의 변화, 행동 패턴 |
| 연구 성격 | LLM 투자 의사결정 프레임워크 | LLM 기반 실험시장·에이전트 기반 모델 |
| 실거래 연결 | 투자분석 어댑터로 활용 가능 | 주문 엔진을 검증하는 샌드박스로 활용 가능 |

따라서 이 논문은 자동매매의 **알파 신호 생성기**라기보다, 주문과 체결이 시장에 어떤 결과를 만드는지 시험하는 **시장 미시구조 실험기**에 가깝다.

## 해결하려는 문제

기존 LLM 금융 시뮬레이션은 다음 요소를 단순화하는 경우가 많다.

1. 모든 주문을 하나의 단일가격으로 일괄 체결한다.
2. 지속되는 호가창이 없다.
3. 시장가와 지정가를 구분하지 않는다.
4. 부분체결과 미체결 잔량을 처리하지 않는다.
5. 매수·매도 호가 차이인 스프레드를 반영하지 않는다.
6. 배당과 현금 이자를 생략한다.
7. 서로 다른 전략과 정보집합을 가진 투자자 간 경쟁을 충분히 구현하지 않는다.
8. LLM의 자연어 설명과 실제 실행 주문을 안정적으로 연결하기 어렵다.

논문은 이를 해결하기 위해 다음 세 요소를 결합한다.

- **시장 계층**: 지속형 주문장과 주문 매칭·청산
- **에이전트 계층**: 자연어 프롬프트로 정의된 이질적 LLM 투자자
- **분석 계층**: 가격·체결·주문·자산·추론 로그의 완전 기록

## 시장 설계

### 거래 방식

논문은 시장을 **연속 복수가격 경매(continuous double auction)** 형태로 설명하지만, LLM 호출 지연 때문에 실제 초단위 연속시장처럼 처리하지 않고 **이산적인 거래 라운드**로 실행한다.

한 라운드 안에서는 에이전트의 제출 순서를 무작위로 섞는다. 특정 에이전트가 매번 먼저 주문을 내서 체결 우선권을 얻는 것을 방지하기 위한 장치다. 무작위화된 이후에는 일반적인 **가격 우선·시간 우선 원칙**을 적용한다.

- 매수 지정가는 높은 가격이 우선한다.
- 매도 지정가는 낮은 가격이 우선한다.
- 가격이 같으면 먼저 등록된 주문이 우선한다.
- 주문 수량이 상대 주문보다 크면 일부만 체결되고 잔량이 남는다.

### 주문 처리 흐름

논문의 설명을 구현 순서로 정리하면 다음과 같다.

```text
1. 주문 형식 및 자산 제약 검증
2. 즉시 교차하지 않는 지정가 주문을 호가창에 등록
3. 반대 방향의 시장가 주문끼리 현재 시장가격으로 상계
4. 남은 시장가 주문을 기존 지정가 호가와 매칭
5. 서로 교차하는 지정가 주문을 가격·시간 우선으로 체결
6. 부분체결 후 잔량 상태 갱신
7. 미체결 시장가 주문은 공격적인 지정가 주문으로 변환 가능
8. 체결가격·수량·매수자·매도자·라운드·시각 기록
9. 현금, 보유주식, 주문예약 금액과 수량 갱신
10. 최종가격, 중간가격, 시장깊이, 스프레드 재계산
```

시장가 주문을 단순히 폐기하지 않고 다른 시장가 주문 또는 기존 호가와 연결한 뒤, 남은 수량을 공격적 지정가로 전환하는 것은 LLM의 비동기 응답 환경에서도 거래가 가능한 상태를 유지하기 위한 설계다.

다만 이 방식은 실제 거래소의 순수한 연속경매와 완전히 같지는 않다. 특히 **시장가 주문끼리 현재 시장가격으로 상계하는 처리**와 **미체결 시장가를 지정가로 바꾸는 규칙**은 이 시뮬레이터가 정의한 별도 시장 규칙이다.

### 주문장 상태

에이전트에게는 다음과 같은 시장깊이 정보가 제공될 수 있다.

```text
Market Depth:
Best Bid: $28.00
Best Ask: $29.00

Sell Orders:
2000 shares @ $57.00
3800 shares @ $50.40
2000 shares @ $30.00
1000 shares @ $29.50
4400 shares @ $29.00

Buy Orders:
1900 shares @ $28.00
1500 shares @ $27.50
2500 shares @ $27.00
```

이를 통해 에이전트는 다음을 판단할 수 있다.

- 최우선 매수호가와 매도호가
- 매수·매도 호가 간 스프레드
- 특정 가격대의 대기 수량
- 얇은 호가 구간과 두꺼운 유동성 구간
- 즉시 체결 가능한 수량
- 지정가 주문을 둘 적절한 가격
- 매수·매도 주문장 불균형

일반적인 분석식으로 표현하면 다음과 같다.

\[
\text{Best Bid}_t = \max(\text{매수 지정가})
\]

\[
\text{Best Ask}_t = \min(\text{매도 지정가})
\]

\[
\text{Spread}_t = \text{Best Ask}_t-\text{Best Bid}_t
\]

\[
\text{Midpoint}_t =
\frac{\text{Best Ask}_t+\text{Best Bid}_t}{2}
\]

논문은 스프레드와 중간가격을 기록하지만, 특정 시장효율성 점수를 하나의 공식으로 정의하지는 않는다.

## 사전 거래 위험검사

주문을 체결하기 전 시스템은 에이전트가 주문을 감당할 수 있는지 검증한다.

### 매수 제약

매수자는 주문에 필요한 현금을 보유해야 한다.

\[
q_{\text{buy}} \times P_{\text{order}}
\leq C_{\text{available}}
\]

현금이 부족하면 주문을 거부하거나 가능한 수량으로 축소한다. 이미 주문에 사용하도록 예약된 현금은 다시 사용할 수 없다.

### 매도 제약

공매도가 허용되지 않으므로 매도 수량은 실제 가용 보유량을 넘을 수 없다.

\[
q_{\text{sell}}
\leq S_{\text{available}}
\]

이미 다른 매도주문에 묶인 주식은 가용 주식에서 제외한다.

### 차입과 공매도 금지

- 현금 차입 금지
- 보유량을 초과하는 공매도 금지
- 주문에 예약된 현금과 주식의 이중 사용 금지

이 제약은 시장의 안정성을 높이지만, 고평가된 가격을 아래로 교정할 수 있는 차익거래 능력도 약화시킨다.

## 현금계정과 배당계정

논문의 예시에서는 현금을 두 계정으로 분리한다.

- **Main Cash Account**: 실제 매매에 사용할 수 있는 현금
- **Dividend Cash Account**: 배당과 이자가 적립되지만 거래에는 사용할 수 없는 현금

예시 포지션 정보는 다음과 같다.

```text
Available Shares: 10000
Main Cash Account: $988500.00
Dividend Cash Account: $296920.65
Total Available Cash: $988500.00
Shares in Orders: 0
Cash in Orders: $11500.00
```

배당과 이자를 재투자하지 못하게 분리한 것은 배당으로 생긴 현금이 다시 매수세로 유입되는 복리효과를 통제하려는 실험 설계로 볼 수 있다. 다만 이는 현실의 일반적인 증권계좌와는 다른 제약이다.

## 자산의 배당 구조

기본 배당은 라운드마다 다음 두 값 중 하나로 정해진다.

\[
D_t =
\begin{cases}
2.40, & p=0.5 \\
0.40, & p=0.5
\end{cases}
\]

기대배당은 다음과 같다.

\[
E[D]
=0.5 \times 2.40+0.5 \times 0.40
=1.40
\]

논문에는 직접 쓰이지 않았지만, 위 분포에서 계산되는 배당 분산과 표준편차는 다음과 같다.

\[
Var(D)
=0.5(2.40-1.40)^2
+0.5(0.40-1.40)^2
=1
\]

\[
\sigma_D=1
\]

즉, 기대배당은 1.40으로 고정돼 있지만 실제 지급액은 매 라운드 0.40 또는 2.40으로 변한다.

## 내재가치 계산

### 무한기간 시장

무한기간 시장의 내재가치는 영구배당 할인모형을 사용한다.

\[
V_t=\frac{E[D]}{r}
\]

기본 설정은 다음과 같다.

- 기대배당 \(E[D]=1.40\)
- 무위험이자율 \(r=0.05\)

따라서 내재가치는 다음과 같다.

\[
V_t=\frac{1.40}{0.05}=28.00
\]

여기서 5%는 연간 이자율이 아니라 **라운드당 이자율로 설정된 실험 파라미터**다. 실제 금융시장 주기와 직접 대응시키면 안 된다.

### 유한기간 시장

현재 라운드가 \(t\), 마지막 라운드가 \(T\), 최종 상환가치가 \(K\)일 때 내재가치는 다음과 같다.

\[
FV_t =
\sum_{\tau=t}^{T}
\frac{E[D]}{(1+r)^{\tau-t+1}}
+
\frac{K}{(1+r)^{T-t+1}}
\]

첫 번째 항은 남은 기간의 기대배당 현재가치이고, 두 번째 항은 마지막 시점의 주식 상환가치다.

논문은 유한기간과 무한기간 시장의 기준가치를 동일하게 만들기 위해 다음처럼 설정한다.

\[
K=\frac{E[D]}{r}
\]

따라서 기본 설정에서는 \(K=28\)이 되고, 만기가 가까워져도 이론적 내재가치가 계속 28로 유지된다. 이는 시간에 따라 내재가치가 자연스럽게 하락하는 실험자산 시장과 달리, **초기가격과 에이전트 행동에 따른 가격발견만 분리해 관찰하려는 보정**이다.

## 가격과 내재가치의 괴리

논문은 시장가격과 내재가치의 관계를 다음 비율로 나타낸다.

\[
\rho=\frac{P}{V}
\]

- \(\rho<1\): 시장가격이 내재가치보다 낮은 저평가 상태
- \(\rho=1\): 시장가격과 내재가치가 일치
- \(\rho>1\): 시장가격이 내재가치보다 높은 고평가 상태

예를 들어 \(V=28\)일 때 다음과 같다.

| \(\rho\) | 시장가격 \(P=\rho V\) | 해석 |
| ---: | ---: | --- |
| 0.5 | 14 | 내재가치의 절반 |
| 0.75 | 21 | 내재가치보다 25% 낮음 |
| 1.0 | 28 | 내재가치와 일치 |
| 1.25 | 35 | 내재가치보다 25% 높음 |
| 2.0 | 56 | 내재가치의 두 배 |
| 3.5 | 98 | 극단적 고평가 |

이 비율은 실험의 초기조건을 만들고 LLM의 매수·매도 경계를 분석하는 핵심 변수로 사용된다.

## 구조화된 의사결정

에이전트의 자연어 답변을 직접 파싱하지 않고 Pydantic 스키마와 함수 호출을 사용한다.

```python
class TradeDecisionSchema(BaseModel):
    valuation_reasoning: str
    valuation: float
    price_target: float
    orders: List[OrderSchema]
    replace_decision: str
    reasoning: str
```

각 주문은 다음 구조를 갖는다.

```python
class OrderSchema(BaseModel):
    decision: Literal["Buy", "Sell"]
    quantity: int
    order_type: str
    price_limit: Optional[float]
```

실제 구현에서는 다음 필드도 함께 요구된다.

- `valuation_reasoning`: 내재가치 계산 근거
- `valuation`: 에이전트가 추정한 현재 내재가치
- `price_target_reasoning`: 다음 가격 예측 근거
- `price_target`: 다음 라운드 목표가격
- `orders`: 하나 이상의 주문 목록
- `replace_decision`: `Add`, `Cancel`, `Replace`
- `reasoning`: 최종 주문 근거

### 주문 예시

```json
{
  "valuation_reasoning": "Expected dividend is 1.40 and the interest rate is 5%. Therefore 1.40 / 0.05 = 28.",
  "valuation": 28.0,
  "price_target_reasoning": "The current market price is 29 and appears stable.",
  "price_target": 29.0,
  "orders": [
    {
      "decision": "Sell",
      "quantity": 1000,
      "order_type": "limit",
      "price_limit": 29.50
    }
  ],
  "replace_decision": "Add",
  "reasoning": "The market price is slightly above my valuation."
}
```

구조화 출력의 목적은 다음과 같다.

1. 주문 필드 누락 방지
2. 자료형 검증
3. 잘못된 시장가·지정가 조합 차단
4. 지정가 주문의 가격 누락 검출
5. 자연어 설명과 실행 주문의 분리
6. 모든 에이전트에 동일한 인터페이스 적용
7. 주문 실패와 재시도 로직 표준화

## 에이전트 유형

### LLM 기반 에이전트

| 유형 | 핵심 행동 |
| --- | --- |
| 가치투자자 | 내재가치보다 낮으면 매수하고 높으면 매도 |
| 모멘텀 트레이더 | 최근 가격과 거래량의 추세를 따라감 |
| 시장조성자 | 양방향 지정가를 제시해 스프레드 수익 추구 |
| 역추세 트레이더 | 과도한 상승·하락 이후 반전을 예상 |
| 투기자 | 시장 비효율과 단기 가격괴리를 탐색 |
| 낙관론자 | 최대 배당 가능성을 실제보다 높게 평가 |
| 비관론자 | 최소 배당 가능성을 실제보다 높게 평가 |
| 개인투자자 | 일반적인 비전문 투자자 행동을 모사 |
| 보유 에이전트 | 거래하지 않고 계속 보유 |

### 시장조성자 세부 규칙

부록의 시장조성자 프롬프트에는 비교적 구체적인 수치가 들어간다.

- 현재가보다 1~3% 낮은 가격에 매수 지정가
- 현재가보다 1~3% 높은 가격에 매도 지정가
- 전체 스프레드는 보통 현재가의 2~6%
- 매수주문보다 10%를 초과해 높은 매도주문 금지
- 최근 변동성이 높으면 스프레드를 넓힘
- 보유재고가 없으면 먼저 매수주문 중심으로 운영
- 보유재고가 많아지면 매수주문을 줄이고 매도를 늘림
- 실제 보유량을 넘는 매도 금지

예를 들어 현재가가 100이면 97~99에 매수호가를, 101~103 부근에 매도호가를 두는 식이다.

### 낙관론자와 비관론자

낙관론자는 최대 배당이 나올 확률을 명시된 50%가 아니라 80~90%로 믿도록 프롬프트된다. 비관론자는 반대로 최소 배당이 나올 확률을 80~90%로 믿는다.

낙관론자의 주관적 기대배당을 최대 확률 85%로 예시 계산하면 다음과 같다.

\[
E[D]_{\text{optimistic}}
=0.85 \times 2.40+0.15 \times 0.40
=2.10
\]

\[
V_{\text{optimistic}}
=\frac{2.10}{0.05}
=42
\]

비관론자가 최소 배당 확률을 85%로 보면 다음과 같다.

\[
E[D]_{\text{pessimistic}}
=0.15 \times 2.40+0.85 \times 0.40
=0.70
\]

\[
V_{\text{pessimistic}}
=\frac{0.70}{0.05}
=14
\]

따라서 동일한 객관적 배당분포를 보더라도 프롬프트로 주관적 확률을 바꾸면 내재가치가 14에서 42까지 벌어질 수 있다. 이 계산은 논문의 프롬프트 설정을 수식으로 풀어 쓴 예시이며, 논문 본문이 특정 확률 85%를 고정해서 사용했다는 뜻은 아니다.

### 규칙 기반 비교 에이전트

LLM 없이 고정 알고리즘으로 움직이는 대조군도 포함한다.

- 항상 매수
- 항상 매도
- 항상 보유
- 갭 트레이더
- 평균회귀 트레이더
- 모멘텀 트레이더
- 고정 스프레드 시장조성자

이들은 LLM 에이전트가 실제로 프롬프트에 따라 차별화된 행동을 보이는지 비교하기 위한 통제조건이다.

## 체계적 의사결정 분석

논문은 LLM의 행동을 해석하기 위해 머신러닝의 부분의존도 그래프와 유사한 실험을 수행한다.

다른 조건은 고정하고 가격·내재가치 비율만 다음 범위에서 변화시킨다.

\[
\rho=\frac{P}{V}, \qquad 0.1 \leq \rho \leq 3.5
\]

각 \(\rho\)에 대해 다음 절차를 수행한다.

```text
1. 목표 비율에 맞춰 시장가격 P = ρV 설정
2. 해당 가격 주변에 일관된 호가창 생성
3. 같은 에이전트 유형으로 여러 번 의사결정 실행
4. 매수·매도·보유 비율 기록
5. 시장가·지정가 선택 기록
6. 주문수량 기록
7. 지정가격과 현재가격의 차이 기록
8. 내재가치와 목표가격 기록
9. 자연어 판단 근거 저장
```

이 실험으로 다음 행동함수를 근사할 수 있다.

\[
a_i = f_i
\left(
\frac{P}{V},
\text{price history},
\text{order book},
\text{inventory},
\text{cash},
\text{prompt}
\right)
\]

여기서 \(a_i\)는 매수·매도·보유와 주문수량·주문유형을 포함한 에이전트 \(i\)의 행동이다.

### 논문에서 관찰된 행동

- 가치투자자는 대체로 \(\rho<1\)에서 매수하고 \(\rho>1\)에서 매도한다.
- 모멘텀 트레이더는 내재가치 비율보다 최근 가격 추세에 더 민감하다.
- 가격이 에이전트의 평가가치에서 크게 벗어날수록 주문수량이 커지는 경향이 있다.
- 시장가격과 평가가치의 차이가 주문 방향과 지정가격을 결정한다.
- 제시된 Figure 3 예시에서는 \(\rho=0.1, 0.67\)에서 매수, \(\rho=1.23\) 이상에서 매도가 나타나며 보유 결정은 보이지 않는다.
- Figure 4 예시에서는 같은 비율에서도 100주와 1,000주 주문이 함께 나타나 LLM 주문수량의 변동성이 확인된다.

다만 v1 논문은 각 지점의 반복 횟수, 신뢰구간, 모델 샘플링 온도, 통계적 유의성 검정을 충분히 제시하지 않는다. 따라서 이 그래프는 정밀한 확률함수 추정보다 **행동 경계를 탐색하는 진단도구**로 보는 편이 적절하다.

## 성과와 시장품질 분석

논문은 다음 분석을 지원한다고 설명한다.

- 거래가격과 내재가치의 수렴
- 체결가격·중간가격·스프레드 시계열
- 에이전트별 현금·주식·총자산
- 절대수익과 수익률
- 에이전트 유형별 부의 재분배
- 유형 간 순매수·순매도 흐름
- 주문 방향 히트맵
- 주문수량과 공격성
- 내재가치 추정치의 변화
- 다음 라운드 목표가격의 정확도
- 자연어 근거의 주요 단어
- 에이전트 구성 변경에 대한 반사실 실험

본문의 설명을 일반적인 식으로 정리하면 에이전트 \(i\)의 시점 \(t\) 총자산은 다음처럼 표현할 수 있다.

\[
W_{i,t}
=
C^{main}_{i,t}
+
C^{div}_{i,t}
+
q_{i,t}M_t
\]

- \(C^{main}_{i,t}\): 거래 가능 현금
- \(C^{div}_{i,t}\): 거래 불가능한 배당·이자 현금
- \(q_{i,t}\): 보유주식
- \(M_t\): 평가가격

유한기간의 마지막 시점에는 주식을 상환가치 \(K\)로 평가하고, 무한기간 실험의 종료 시점에는 마지막 시장가격으로 평가한다.

\[
R_{i,t}
=
\frac{W_{i,t}-W_{i,0}}{W_{i,0}}
\]

다만 논문은 목표가격 오차나 시장효율성을 하나의 고정된 손실함수로 정의하지 않는다. 실제 재현 시에는 MAE, RMSE, 가격괴리, 평균 스프레드, 체결률 등을 별도로 명시해야 한다.

## 주요 실험 결과

### 전략 준수

LLM 에이전트는 같은 GPT-4o를 사용해도 시스템 프롬프트에 따라 서로 다른 행동을 보였다.

- 가치투자자는 가격과 내재가치를 비교한다.
- 모멘텀 에이전트는 최근 가격흐름을 중시한다.
- 시장조성자는 양방향 지정가를 제시한다.
- 낙관론자와 비관론자는 같은 배당정보를 다르게 해석한다.

이는 에이전트의 이질성이 모델 파라미터가 아니라 프롬프트 차이만으로도 만들어질 수 있음을 보여준다.

### 프롬프트 준수와 수익극대화의 차이

논문은 LLM이 시장 상황을 이해하면서도 손실이 발생할 수 있는 전략을 계속 유지한다고 본다. 이는 LLM이 다음 목적함수를 명시적으로 최적화하지 않기 때문이다.

\[
\max E[W_T]
\]

또는

\[
\max E[U(W_T)]
\]

실제 시스템에는 이런 이익·효용 목적함수나 강화학습 보상이 없다. LLM은 주어진 언어지시를 잘 따르는 방향으로 행동한다.

따라서 “LLM이 거래할 수 있다”는 결과는 “LLM이 장기적으로 초과수익을 낸다”는 뜻이 아니라 다음 능력을 확인한 것이다.

- 시장정보 읽기
- 내재가치 계산
- 주문 방향 선택
- 주문유형 선택
- 수량과 가격 지정
- 포지션 제약 준수
- 역할 프롬프트 유지

### 비대칭적 가격발견

무한기간 실험에서 다음 비대칭이 관찰된다.

- 초기 가격이 14인 저평가 시장은 가격이 28 부근으로 빠르게 상승한다.
- 초기 가격이 56인 고평가 시장은 15라운드 내에 28로 충분히 하락하지 않는다.
- 고평가 시장에서는 에이전트의 가치평가도 높은 시장가격에 끌려가는 경향이 있다.
- 저평가 시장에서는 에이전트 평가가 내재가치 방향으로 상향 조정된다.

논문은 이를 LLM 에이전트가 저평가 교정에는 상대적으로 강하지만 고평가 교정에는 약하다는 결과로 해석한다.

### 가능한 메커니즘 해석

논문이 인과적으로 검증한 것은 아니지만 다음 설계가 비대칭을 강화했을 가능성이 있다.

1. **공매도 금지**  
   고평가를 확신해도 보유주식이 없으면 추가 매도를 할 수 없다.

2. **차입 금지**  
   레버리지를 사용한 차익거래가 불가능하다.

3. **낙관론자 포함**  
   지속적인 고평가 수요가 존재한다.

4. **시장조성자의 큰 자산**  
   시장조성자가 기본 에이전트의 20배 자산을 가지므로 가격형성에 큰 영향을 줄 수 있다.

5. **가격 앵커링**  
   LLM이 현재가격과 최근가격을 내재가치 추정에 반영해 기존 고평가를 정당화할 수 있다.

6. **짧은 15라운드**  
   장기적으로 수렴할 가능성을 배제할 수 없다.

따라서 고평가 지속을 LLM 고유의 버블 성향이라고 단정하려면 공매도 허용 여부, 에이전트 구성, 초기자산, 프롬프트, 반복실험을 각각 통제해야 한다.

## 자동매매 시스템 설계에 주는 시사점

### 1. 주문 시뮬레이터를 리서치 모델과 분리한다

LLM의 매수·매도 의견을 실제 주문으로 바로 보내지 않고 다음 계층을 분리해야 한다.

```text
LLM 판단
  └─ 구조화 주문안
       └─ Python 위험규칙
            └─ 독립된 시장 시뮬레이터
                 └─ 체결·부분체결·미체결 평가
                      └─ 실주문 여부 결정
```

### 2. 주문안은 방향만 저장하면 부족하다

최소한 다음 필드를 남겨야 한다.

```json
{
  "symbol": "AAPL",
  "side": "buy",
  "quantity": 10,
  "order_type": "limit",
  "limit_price": 180.0,
  "time_in_force": "DAY",
  "valuation": 195.0,
  "price_target": 188.0,
  "max_loss": 50.0,
  "invalidation_condition": "close below 175",
  "reasoning": "...",
  "data_timestamp": "...",
  "model": "...",
  "prompt_hash": "..."
}
```

### 3. 시장가 주문도 체결가격이 확정된 것은 아니다

실제 시장에서는 시장가 주문도 다음 영향을 받는다.

- 스프레드
- 주문장 깊이
- 시장충격
- 부분체결
- 거래지연
- 급격한 호가이동
- 거래정지
- 최소 호가단위

따라서 백테스트에서 단순히 종가에 전량 체결시키면 안 된다.

### 4. 프롬프트는 전략이면서 위험요인이다

같은 기반모델을 여러 에이전트가 사용하면 유사한 시장신호에 동시 반응할 수 있다. 서로 다른 역할 이름만 주는 것으로 충분하지 않으며 다음도 다양화해야 한다.

- 정보집합
- 관측주기
- 위험한도
- 주문규칙
- 모델 계열
- 프롬프트 템플릿
- 샘플링 설정
- 메모리
- 평가가치 계산법

### 5. 시장 시뮬레이터는 실제 증권 주문과 완전히 분리한다

이 논문의 프레임워크는 실험용 가상시장이다. 실제 주문 API와 연결하려면 다음을 별도로 구현해야 한다.

- 거래소별 호가단위
- 주문 가능 시간
- 정정·취소 규칙
- 수수료와 세금
- 증거금과 결제주기
- 가격제한폭
- 공매도 규제
- 주문거부 코드
- 네트워크 지연
- 브로커 API 재시도
- 주문·체결 원장 대사

## 한계와 검증 포인트

### 실험결과의 통계적 한계

- v1은 주요 결과를 소수의 예시 시뮬레이션과 그림으로 제시한다.
- 반복 횟수와 독립적인 랜덤 시드 수가 명확하지 않다.
- 평균, 표준편차, 신뢰구간, 가설검정이 충분히 제시되지 않는다.
- 모델 출력의 temperature, top-p, API 스냅샷 같은 추론 설정이 본문에 없다.
- LLM의 확률적 변동과 시장 무작위성의 효과를 분리하지 않는다.
- 같은 조건을 여러 번 실행했을 때 결과가 재현되는지 확인이 필요하다.

### 시장 미시구조의 한계

- 거래비용이 0이다.
- 공매도와 차입이 금지된다.
- 배당현금과 이자를 거래에 재사용할 수 없다.
- LLM 지연을 이산 라운드와 무작위 순서로 근사한다.
- 시장가끼리 현재가격으로 상계하는 규칙은 실제 거래소와 다를 수 있다.
- 미체결 시장가를 공격적 지정가로 전환하는 규칙도 별도 가정이다.
- 틱 크기, 거래정지, 호가취소 지연, 큐 포지션 같은 현실 요소가 제한적이다.
- 시장조성자에게 기본 대비 20배 자산을 주는 설정은 결과를 크게 좌우할 수 있다.

### 금융적 한계

- 실제 기업이나 실제 뉴스·재무데이터를 사용하지 않는다.
- 하나의 배당지급 자산만 다룬다.
- 거래비용·세금·슬리피지가 없다.
- 위험조정수익률이나 실제 투자전략 성과를 검증하지 않는다.
- 라운드당 5% 이자율은 현실적인 시간단위와 대응하지 않는다.
- 실험의 가격수렴을 실제 시장의 알파 창출로 해석하면 안 된다.

### LLM 평가의 한계

- GPT-4o 중심 실험이므로 다른 모델에서 동일한 결과가 보장되지 않는다.
- 자연어 추론은 설명처럼 보이지만 실제 내부 의사결정 과정과 동일하다고 볼 수 없다.
- 평가가치와 목표가격이 시장가격에 앵커링될 수 있다.
- 프롬프트를 정확히 따르는 것이 수익성과 같지 않다.
- 동일 기반모델의 상관행동을 주장하지만 모델 간 정량 비교는 제한적이다.
- 에이전트가 자신의 과거 손익을 보고 전략을 수정하는 학습구조는 핵심 실험에 포함되지 않는다.

## 이 논문을 프로젝트에 적용하는 방법

이 논문에서 직접 가져올 수 있는 부분은 **주문·체결 실험기**다.

```text
실제 Toss 주문 시스템
  └─ 직접 연결 금지

리서치 판단
  ├─ TradingAgents 보고서
  ├─ 사실·주관 분리 보고서
  ├─ 기술지표·차트 분석
  └─ 위험검토 결과
       ↓
가상 주문 생성
       ↓
독립 시장 시뮬레이터
  ├─ 시장가·지정가
  ├─ 부분체결
  ├─ 호가잔량
  ├─ 스프레드
  ├─ 수수료
  ├─ 슬리피지
  ├─ 주문취소·정정
  └─ 체결지연
       ↓
가상 손익 및 위험평가
       ↓
검증을 통과한 전략만 별도 실거래 후보로 승격
```

논문의 그대로 구현하기보다 다음을 보강하는 것이 적절하다.

1. 실제 또는 재구성된 호가데이터 사용
2. 수수료·세금·슬리피지 추가
3. 주문 크기에 따른 시장충격
4. IOC·FOK·DAY·GTC 등 유효기간
5. 거래소 틱 크기와 가격제한폭
6. 장 시작·마감 동시호가
7. 부분체결 후 주문 정정

## 핵심 결론

이 논문의 가장 큰 기여는 LLM에게 “매수할까?”라고 묻는 데 있지 않다. 자연어로 정의된 여러 투자자를 하나의 시장에 넣고, 이들이 제출한 구조화 주문을 실제 주문장 규칙에 따라 체결해 **가격과 유동성이 어떻게 만들어지는지 관찰할 수 있게 한 것**이 핵심이다.

논문이 보여준 것은 다음과 같다.

- LLM은 가치투자자·모멘텀·시장조성자 같은 역할을 수행할 수 있다.
- 자연어 프롬프트만으로 서로 다른 투자신념과 거래행동을 만들 수 있다.
- LLM의 내재가치·목표가격·주문을 구조화된 데이터로 기록할 수 있다.
- 주문장과 부분체결을 포함하면 에이전트 행동이 시장가격에 직접 영향을 준다.
- 저평가와 고평가의 교정 속도가 비대칭적으로 나타날 수 있다.
- 프롬프트 준수는 수익극대화와 다르다.
- 같은 기반모델을 사용하는 다수의 에이전트는 상관된 행동을 일으킬 수 있다.
- 시뮬레이션 결과를 실거래 수익성으로 일반화해서는 안 된다.

따라서 이 프레임워크는 실제 주문 엔진이 아니라, **LLM 판단이 주문장·체결·가격발견에 어떤 영향을 주는지 검증하는 독립된 실험환경**으로 사용하는 것이 가장 적절하다.
