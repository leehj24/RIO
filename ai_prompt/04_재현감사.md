# Beyond Agent Architecture: LLM 트레이딩의 실행 가정과 재현성 감사

## 서지 정보

* 원제: *Beyond Agent Architecture: Execution Assumptions and Reproducibility in LLM-Based Trading Systems*
* 저자: Junyi Yao, Zihao Zheng
* 버전: arXiv:2606.08285v1
* 제출일: 2026-06-06
* 분야: LLM 트레이딩, 멀티 에이전트, 백테스트 재현성, 실행 현실성, 거래비용
* 원문: [https://arxiv.org/pdf/2606.08285](https://arxiv.org/pdf/2606.08285)
* 분류: Artificial Intelligence, Computational Finance, Trading and Market Microstructure

이 논문은 30개의 거래 관련 LLM 연구를 대상으로 데이터 시점, 학습·검증·테스트 분리, 거래비용, 회전율, 주문 체결 시점, 투자 유니버스 및 코드·프롬프트 공개 수준을 감사한다. 별도로 미국 대형주 10종목을 이용한 간단한 실험을 통해 실행 시점과 비용 가정만 바뀌어도 전략 성과가 크게 달라질 수 있음을 보여준다. ([arXiv][1])

## 한눈에 보기

이 논문의 핵심 주장은 다음과 같다.

> 에이전트가 얼마나 정교하게 토론하고 추론했는지만으로는 트레이딩 성능을 평가할 수 없다.
> 어떤 데이터를 언제 알 수 있었는지, 신호가 언제 주문으로 변환됐는지, 실제 비용을 얼마나 부담했는지까지 알아야 수익률을 해석할 수 있다.

LLM 트레이딩 결과는 모델과 프롬프트만으로 결정되지 않는다.

```text
LLM·에이전트 아키텍처
        +
입력 데이터의 시점
        +
학습·검증·테스트 구간
        +
신호 생성 시점
        +
주문 제출·체결 시점
        +
수수료·스프레드·슬리피지
        +
포트폴리오 회전율
        +
종목 유니버스 선정 방식
        +
모델·프롬프트·코드 버전
        =
최종 백테스트 결과
```

예를 들어 종가 데이터를 모두 본 뒤 같은 종가에 체결했다고 가정하면 현실에서는 불가능한 수익이 들어갈 수 있다. 거래가 잦은 전략은 비용 전에는 우수해 보여도 수수료, 스프레드와 슬리피지를 적용하면 초과수익이 사라질 수 있다. 현재 살아남은 종목만 과거 시점에도 존재한 것처럼 사용하면 생존자 편향이 발생한다. ([arXiv][2])

## 해결하려는 문제

기존 LLM 트레이딩 연구는 다음과 같은 요소를 상세하게 설명하는 경우가 많다.

* 분석가·트레이더·위험관리자 역할
* 에이전트 간 토론 과정
* 메모리와 자기반성
* 뉴스·재무·기술지표 결합
* 도구 호출과 검색 과정
* 최종 매수·매도 근거

그러나 다음과 같은 실제 평가 조건은 상대적으로 불명확한 경우가 많다.

* 입력 뉴스가 의사결정 전에 실제로 공개됐는가
* 재무 데이터가 당시 이용 가능했던 원본인가
* 종가 신호를 당일 종가에 체결했는가
* 신호와 체결 사이에 지연이 있었는가
* 거래비용과 스프레드를 반영했는가
* 포트폴리오 회전율을 보고했는가
* 테스트 구간을 튜닝에 사용하지 않았는가
* 현재 종목 구성으로 과거를 백테스트했는가
* 정확한 모델 버전과 프롬프트가 보존됐는가

논문은 이 문제를 **아키텍처의 정교함과 평가 프로토콜의 엄밀함 사이의 격차**로 정의한다. ([arXiv][2])

## 리뷰 범위와 문헌 선정 방법

논문은 2023년 1월 1일부터 2026년 5월 30일까지 공개된 영어 연구 중 다음과 관련된 자료를 조사했다.

* 직접 매매 시스템
* 포트폴리오 구성
* 알파 팩터 발굴
* LLM 기반 금융 의사결정
* 거래 결과에 연결되는 금융 벤치마크
* 실시간·준실시간 거래 평가

검색에는 Google Scholar, arXiv, IEEE Xplore, ACM Digital Library, SSRN 및 기존 논문의 참고문헌 역추적이 사용됐다. 검색 결과 68개 후보 중 11개가 중복·비연구 자료·접근 불가 등의 이유로 제거됐고, 57개를 제목과 초록 수준에서 검토했다. 이 중 15개는 배경·메타 리뷰로 남기고 30개를 최종 재현성 감사 대상으로 선정했다. ([arXiv][2])

```text
검색 및 참고문헌 추적
        │
        └─ 후보 68개
              │
              ├─ 중복·접근 불가·비연구 자료 11개 제외
              │
              └─ 제목·초록 검토 57개
                     │
                     ├─ 거래 관련성이 낮은 연구 12개 제외
                     ├─ 배경·메타 리뷰 15개
                     └─ 최종 감사 대상 30개
```

저자들은 이를 완전한 체계적 문헌고찰이나 모든 금융 LLM 논문의 전수조사라고 주장하지 않는다. PRISMA 형태의 투명한 선별 기록을 참고한 **범위가 제한된 주제 리뷰**다. ([arXiv][2])

## 핵심 감사 항목

### 1. Point-in-Time 데이터

Point-in-Time 데이터는 의사결정 시점에 실제로 이용 가능했던 정보만 사용하는 것을 의미한다.

[
available_at(x) \le decision_time_t
]

예를 들어 2024년 3월 1일의 매매 판단에는 다음 정보가 들어가면 안 된다.

* 이후 수정된 재무제표
* 미래에 공개된 뉴스
* 사후 정정된 경제지표
* 미래 시점의 지수 구성 종목
* 미래 가격을 이용해 계산한 기술지표
* 최신 LLM이 이미 학습한 미래 사건 정보

LLM 시스템에서는 모델 자체의 사전학습 지식도 데이터 누출 경로가 될 수 있다. 따라서 과거 시점 백테스트에서는 프롬프트 데이터뿐 아니라 모델 지식의 기준 시점과 검색 도구의 반환 범위도 관리해야 한다. 논문은 이러한 시점 통제가 미래 정보가 프롬프트, 검색, 특징값 또는 벤치마크 라벨로 들어오는 것을 방지한다고 설명한다. 

### 2. 시간 구간 분리

학습·검증·테스트 기간을 날짜 단위로 명확하게 공개해야 한다.

```yaml
temporal_split:
  train:
    start:
    end:

  validation:
    start:
    end:

  test:
    start:
    end:

  embargo_period:
  purge_window:
```

단순히 “2020년부터 2024년까지 데이터를 사용했다”고 적는 것은 충분하지 않다. 다음 구분이 필요하다.

* 모델 학습 구간
* 프롬프트와 임계값을 선택한 구간
* 전략 파라미터를 튜닝한 구간
* 최종 성능만 평가한 미사용 구간
* 테스트 직전 정보 누출을 막기 위한 purge 또는 embargo 구간

논문은 기간 전체만 공개하고 내부 튜닝 구조를 설명하지 않으면 시장 국면 분리와 하이퍼파라미터 누출을 판단하기 어렵다고 지적한다. ([arXiv][2])

### 3. 실행 시점

신호가 생성된 시간과 주문이 실제로 체결된 시간을 분리해야 한다.

```text
시장 데이터 관측
      ↓
신호 생성
      ↓
LLM 추론 완료
      ↓
위험 검토 완료
      ↓
주문 제출
      ↓
거래소 도착
      ↓
부분 또는 전체 체결
```

최소한 다음 중 어떤 체결 규칙을 사용했는지 명시해야 한다.

| 실행 규칙             | 의미                                 |
| ----------------- | ---------------------------------- |
| Same close        | 당일 종가 정보로 신호를 만들고 당일 종가 체결         |
| Next open         | 당일 종가 이후 신호를 만들고 다음 거래일 시가 체결      |
| Next close        | 당일 종가 이후 신호를 만들고 다음 거래일 종가 수익으로 평가 |
| Event time        | 뉴스·공시 시각 이후 일정 지연을 두고 체결           |
| Order-book fill   | 호가창에서 지정가·시장가·부분체결을 시뮬레이션          |
| Delayed execution | 모델 추론 및 주문 전송 시간을 반영해 이후 가격으로 체결   |

종가 정보를 모두 사용한 신호를 같은 종가로 체결하는 것은 일반적으로 정당화하기 어렵다. 논문은 이를 같은 기간 실행과 지연 실행을 구분해야 하는 대표적인 사례로 제시한다. ([arXiv][2])

### 4. 거래비용과 포트폴리오 회전율

수익률은 거래비용 차감 전 `gross return`과 차감 후 `net return`을 분리해야 한다.

거래비용에는 다음이 포함될 수 있다.

```text
증권사 수수료
거래소 수수료
매수·매도 스프레드
시장가 슬리피지
시장충격
세금
환전비용
차입비용
공매도 대차비용
주문 미체결 비용
```

매매전략이 자주 포지션을 바꾼다면 낮은 수수료도 장기간 누적돼 큰 성과 차이를 만든다. 논문 감사 결과에서도 비용 또는 회전율 처리가 가장 적게 복구된 항목이었다. ([arXiv][2])

### 5. 투자 유니버스

다음 사항을 명확히 기록해야 한다.

* 어떤 시장과 자산군을 사용했는가
* 종목은 어떤 규칙으로 포함됐는가
* 상장폐지 종목을 포함했는가
* 당시 지수 구성 종목을 사용했는가
* 거래정지·유동성 부족 종목을 제외했는가
* 최소 시가총액과 거래대금 기준은 무엇인가
* 종목 교체가 발생한 시점은 언제인가

현재 시점에 살아남은 우량주를 선택한 뒤 과거 전체 기간을 백테스트하면 생존자 편향과 사후 선택 편향이 발생할 수 있다. 

### 6. 재현성 아티팩트

논문은 다음 자료가 재현성에 필요하다고 본다.

* 코드
* 정확한 프롬프트
* 시스템 프롬프트
* 모델 제공자와 모델 버전
* 도구와 라우팅 설정
* 원본 데이터 식별자
* 입력 데이터 스냅샷
* 랜덤 시드
* 실패 시 재시도 정책
* 결과 로그
* 벤치마크 버전

코드가 공개돼도 폐쇄형 모델의 버전이 바뀌거나 API 응답이 달라지면 결과를 완전히 재현하기 어렵다. 모델 이름만이 아니라 호출 날짜, 모델 스냅샷, 온도, 시드, retry 정책까지 보존해야 한다. ([arXiv][2])

## Y·P·NR 평가 체계

논문은 각 항목을 다음 세 단계로 평가한다.

| 코드   | 의미                                     |
| ---- | -------------------------------------- |
| `Y`  | 독자가 해당 가정을 재구현하거나 스트레스 테스트할 정도로 명확히 공개 |
| `P`  | 일부 정보는 있으나 완전한 구현에는 부족                 |
| `NR` | 공개 논문이나 연결된 자료에서 해당 내용을 복구하지 못함        |

중요한 점은 `NR`이 반드시 “논문에서 실행하지 않았다”는 뜻은 아니라는 것이다. 비공개 코드에는 구현돼 있을 수 있지만 공개 자료에서 확인되지 않았다는 의미다.

또한 `P`는 실패 판정이 아니다. 비용을 반영했다고 언급했더라도 수수료율, 슬리피지 계산, 회전율 산식이나 체결 기준이 부족하면 `P`가 된다. ([arXiv][2])

## 감사 검증 과정

첫 번째 저자가 30개 연구를 초기 코딩하고, 두 번째 저자가 각 연구의 다음 다섯 항목을 다시 검토했다.

```text
Split / Point-in-Time
Held-out evaluation
Costs
Execution
Artifacts
```

총 검증 항목은 다음과 같다.

[
30\text{개 연구}\times5\text{개 항목}=150\text{개 검증}
]

150개 항목 모두 저자 간 최종 합의 코드가 부여됐고, 동결된 증거 행렬에는 미해결 의견 차이가 없었다. 다만 이것은 각 논문이 완전히 재현 가능하다는 의미가 아니라, 저자들이 최종 감사 코드에 합의했다는 의미다. ([arXiv][2])

## 30개 연구 감사 결과

| 감사 항목                  | 복구 가능한 연구 |    비율 |
| ---------------------- | --------: | ----: |
| 실행 시점 또는 실행 의미         |     26/30 | 86.7% |
| Point-in-Time 또는 시간 분할 |     25/30 | 83.3% |
| 명확한 홀드아웃 평가            |     21/30 | 70.0% |
| 재현성 아티팩트               |     18/30 | 60.0% |
| 비용 또는 회전율 처리           |     14/30 | 46.7% |

여기서 “복구 가능”은 `Y`만이 아니라 일부 `P`도 포함한다. 특히 비용 항목의 14개는 비용 처리가 완전히 구현 가능할 정도로 공개됐다는 뜻이 아니라, 부분적으로라도 비용이나 회전율 정보를 확인할 수 있었다는 뜻이다. ([arXiv][2])

가장 큰 문제는 **거래비용·슬리피지·회전율**이다. 30개 연구 중 절반 이상은 공개 자료만으로 비용 민감도를 충분히 검증하기 어려웠다.

## LLM-Proxy의 정확한 의미

여기서 `LLM-Proxy`라는 이름에 주의해야 한다.

이 전략은 실제 GPT API나 로컬 LLM을 매일 호출하지 않는다. 멀티 에이전트도 아니며, 언어모델이 직접 자연어 뉴스를 분석하는 구조도 아니다.

실제로는 LLM의 조심스러운 일별 판단 프롬프트를 모방한 **고정 수식 기반 결정 규칙**이다. 결정 과정은 완전히 결정론적이며 다음 요소가 없다.

* 모델 호출
* 샘플링 온도
* 반복 프롬프트
* 모델 버전 변화
* 자연어 생성의 무작위성

따라서 이 실험은 “LLM이 수익을 냈다”는 증거가 아니라, LLM형 의사결정 구조를 단순 규칙으로 표현해 실행 가정의 효과를 보여주는 예시다. ([arXiv][2])

## LLM-Proxy 점수 계산

각 종목 (i)의 시점 (t) 점수는 다음과 같다.

[
S_{i,t}
=======

0.45\mathbf{1}(MA_5>MA_{20})
+
0.30\operatorname{sgn}(Mom_{20})
+
0.20F_{i,t}
+
0.15M_t
]

각 항목은 다음을 의미한다.

| 항목                             | 의미                      |   계수 |
| ------------------------------ | ----------------------- | ---: |
| (\mathbf{1}(MA_5>MA_{20}))     | 5일 이동평균이 20일 이동평균보다 높은지 | 0.45 |
| (\operatorname{sgn}(Mom_{20})) | 20일 모멘텀의 방향             | 0.30 |
| (F_{i,t})                      | 최근 기업 이벤트 대용 신호         | 0.20 |
| (M_t)                          | VIX 기반 거시 국면 신호         | 0.15 |

[
S_{i,t}>0.35
]

이면 해당 종목에 임시 `LONG` 신호를 부여한다. 선택된 종목들은 롱온리 포트폴리오로 정규화하며 종목별 최대 비중은 10%다. ([arXiv][2])

### 계산식 해석

각 계수의 합은 다음과 같다.

[
0.45+0.30+0.20+0.15=1.10
]

따라서 이 점수는 합이 1인 확률 가중평균이 아니다. 여러 방향 신호를 결합한 휴리스틱 점수다.

또한 논문 본문에는 (F_{i,t})와 (M_t)의 정확한 이산화 임계값과 전체 생성 규칙이 식 수준으로 모두 제시되지는 않는다. 본문에서는 다음 정도를 설명한다.

* (F_{i,t}): 큰 종가 변동일을 기업 이벤트의 대리값으로 사용하고 다음 이벤트까지 최근 부호를 유지
* (M_t): FRED의 VIXCLS를 바탕으로 만든 거시 국면 대리값

실제 재현에는 LaTeX 프로젝트 또는 보충 코드의 정확한 임계값 확인이 필요하다. ([arXiv][2])

## Structured-Only 제거 실험

`Structured-Only` 전략은 기업 이벤트 항 (F_{i,t})을 0으로 만든다.

[
S^{structured}_{i,t}
====================

0.45\mathbf{1}(MA_5>MA_{20})
+
0.30\operatorname{sgn}(Mom_{20})
+
0.15M_t
]

나머지 조건은 동일하게 유지한다.

* 동일한 점수 계수
* 동일한 매수 임계값
* 동일한 종목별 10% 상한
* 동일한 포트폴리오 정규화
* 동일한 거래비용
* 동일한 실행 시점

이를 통해 가격·거시 구조만 사용한 경우와 이벤트 대리 신호를 추가한 경우를 비교한다. ([arXiv][2])

다만 기업 이벤트 신호가 실제 뉴스나 공시에서 생성된 것이 아니라 **이미 발생한 가격 급등락에서 다시 만들어진 변수**라는 점에 주의해야 한다. 따라서 이 제거 실험은 진정한 텍스트 정보의 추가 가치를 증명하지 않는다.

## 데이터 출처와 정렬

| 입력        | 출처 및 처리                                     |
| --------- | ------------------------------------------- |
| 주가        | 공개 GitHub·Zenodo의 일별 OHLCV CSV              |
| 거시 변수     | FRED VIXCLS                                 |
| 기업 이벤트    | 큰 종가 변동으로 만든 로컬 대리 신호                       |
| 날짜 정렬     | 모든 주가와 거시 데이터의 공통 날짜 교집합                    |
| 결측 거시 데이터 | 누락된 시장일에 이전 값 forward-fill                  |

기업 이벤트는 실제 시점별 뉴스 피드가 아니라 가격 변동을 사용한 대리변수다. 저자들도 이를 기관용 텍스트 피드 대신 사용하는 보수적 대리값이라고 제한한다. ([arXiv][2])

## 실행 순서

논문의 예시 실험은 같은 종가 체결 문제를 피하기 위해 다음 순서를 사용한다.

```text
day t 종가 확정
      ↓
이동평균·모멘텀·이벤트·VIX 신호 계산
      ↓
포트폴리오 비중 w(i,t) 결정
      ↓
day t+1의 close-to-close 수익률로 전략 평가
```

논문은 이를 `next-day close-to-close proxy`라고 부른다. 이는 완전한 주문 체결 시뮬레이션은 아니지만, 적어도 당일 종가를 본 뒤 같은 종가에 체결하는 방식은 피한다. ([arXiv][2])

실제 시스템에서는 이를 더 구체적으로 다음처럼 분리해야 한다.

```yaml

  llm_response_time:
  risk_check_time:
  order_submit_time:
  exchange_arrival_time:
  first_fill_time:
  final_fill_time:
```

## 포트폴리오 수익률 계산

### 개별 종목 수익률

[
r_{i,t+1}
=========

\frac{P_{i,t+1}}{P_{i,t}}-1
]

### 비용 차감 전 포트폴리오 수익률

[
R^{gross}_{t+1}
===============

\sum_i w_{i,t}r_{i,t+1}
]

* (w_{i,t}): 시점 (t) 신호가 생성된 후 종목 (i)의 목표 비중
* (r_{i,t+1}): 다음 기간 종목 (i)의 수익률

### 포트폴리오 회전율

[
TO_t
====

\sum_i
\left|
w_{i,t}-w_{i,t-1}
\right|
]

예를 들어 종목 A의 비중이 0%에서 10%로 늘고 종목 B가 10%에서 0%로 줄면 다음과 같다.

[
TO_t=|0.10-0|+|0-0.10|=0.20
]

이 정의에서는 매도와 매수를 모두 합산하기 때문에 전체 포트폴리오를 완전히 교체하면 회전율이 2에 근접할 수 있다.

### 비용 차감 후 수익률

[
R^{net}_{t+1}
=============

## R^{gross}_{t+1}

cTO_t
]

* (c): 회전율 단위당 거래비용
* 10 bps:

[
c=0.001
]

* 25 bps:

[
c=0.0025
]

논문은 비용을 0 bps, 10 bps, 25 bps로 바꿔 결과 민감도를 비교한다. 이 값들은 특정 거래소의 실제 비용을 대표하려는 것이 아니라 비용 가정에 따라 전략 순위가 얼마나 달라지는지 확인하는 스트레스 설정이다. ([arXiv][2])

## 평가 지표

### 누적수익률

[
CR_T
====

\prod_{t=1}^{T}
(1+R^{net}_t)-1
]

논문의 `Final Cum. Return`은 최종 자산가치 자체가 아니라 초기 자산 대비 누적수익률이다.

따라서 표의 `1.3068`은 자산이 1.3068배가 됐다는 뜻이 아니라 다음을 의미한다.

[
1.3068=130.68%
]

최종 자산 배수는 다음과 같다.

[
1+1.3068=2.3068
]

### 연환산수익률

거래일 수가 (T)일 때 252 거래일 기준으로 환산한다.

[
AR
==

(1+CR_T)^{252/T}-1
]

### 연환산 변동성

[
\sigma_{ann}
============

\sigma_{daily}\sqrt{252}
]

논문은 일별 수익률의 모집단 표준편차를 사용한다고 명시한다.

### 샤프지수

[
Sharpe
======

\frac{\bar R-r_f}{\sigma_R}
\sqrt{252}
]

예시에서는 다음과 같이 무위험수익률을 0으로 둔다.

[
r_f=0
]

### 소티노지수

[
Sortino
=======

\frac{\bar R-r_f}
{\sigma_{downside}}
\sqrt{252}
]

소티노지수는 전체 변동성이 아니라 하방 변동성만 위험으로 본다.

### 최대낙폭

[
MDD
===

\min_t
\left(
\frac{W_t-\max_{s\le t}W_s}
{\max_{s\le t}W_s}
\right)
]

논문은 누적수익률, 연환산수익률, 샤프, 소티노, 최대낙폭, 연환산 변동성과 회전율을 보고한다. 다만 본문은 연환산수익률과 변동성의 convention을 설명하지만 샤프·소티노의 세부 구현식 전체를 직접 수식으로 제시하지는 않는다. ([arXiv][2])

## 10 bps 비용 적용 결과

| 전략              |   누적수익률 | 연환산수익률 | Sharpe | Sortino |     MDD | 연환산 변동성 |    회전율 |
| --------------- | ------: | -----: | -----: | ------: | ------: | ------: | -----: |
| Buy and Hold    | 119.95% | 70.57% | 3.1958 |  5.7050 |  -8.89% |  17.19% | 0.0009 |
| Moving Average  | 109.80% | 65.20% | 2.6091 |  4.9904 | -13.59% |  20.02% | 0.2058 |
| LLM-Proxy       | 130.68% | 76.16% | 2.8685 |  5.5417 | -11.83% |  20.49% | 0.2902 |
| Structured-Only | 115.58% | 68.26% | 2.4299 |  4.7811 | -13.55% |  22.46% | 0.2740 |

10 bps에서는 LLM-Proxy가 가장 높은 누적수익률을 기록했다. 그러나 위험조정수익 측면에서는 Buy and Hold의 샤프지수 3.1958이 LLM-Proxy의 2.8685보다 높고, 최대낙폭도 Buy and Hold가 더 작다. 따라서 “LLM-Proxy가 모든 기준에서 우수하다”는 결과가 아니다. ([arXiv][2])

## 거래비용 민감도

| 전략              |   0 bps |  10 bps |  25 bps | 10 bps 감소 | 25 bps 감소 |
| --------------- | ------: | ------: | ------: | --------: | --------: |
| Buy and Hold    | 119.95% | 119.95% | 119.95% |    0.00%p |    0.00%p |
| Moving Average  | 124.20% | 109.80% |  89.91% |  -14.39%p |  -34.29%p |
| LLM-Proxy       | 147.10% | 130.68% | 108.06% |  -16.42%p |  -39.04%p |
| Structured-Only | 134.73% | 115.58% |  89.71% |  -19.16%p |  -45.02%p |

LLM-Proxy는 비용이 없을 때 147.10%로 Buy and Hold보다 27.15%포인트 높다.

[
147.10-119.95=27.15%\mathrm{p}
]

하지만 25 bps 비용을 적용하면 다음과 같이 Buy and Hold보다 낮아진다.

[
108.06-119.95=-11.89%\mathrm{p}
]

즉 낮은 비용 가정에서는 우수해 보이던 능동 전략이 높은 비용 가정에서는 단순 보유전략보다 뒤처진다. 이것이 예시 실험이 보여주려는 핵심이다. ([arXiv][2])

## 하위 기간 안정성 검사

10 bps 비용을 적용한 결과는 다음과 같다.

| 전략              |  2023년 | 2024년 YTD |
| --------------- | -----: | --------: |
| Buy and Hold    | 64.01% |    34.11% |
| Moving Average  | 54.01% |    36.23% |
| LLM-Proxy       | 69.22% |    36.32% |
| Structured-Only | 55.93% |    38.25% |

2023년에는 LLM-Proxy가 가장 높지만, 2024년 1월 1일부터 6월 26일까지는 Structured-Only가 38.25%로 가장 높다.

따라서 기업 이벤트 대리 신호를 추가한 전략이 모든 하위 기간에서 일관되게 우수한 것은 아니다. 저자들도 하위 기간에서는 전략 순위 차이가 줄어든다고 설명한다. ([arXiv][2])

## 입력 데이터 시점 원장

뉴스와 공시는 하나의 시간 필드만 저장하면 부족하다.

```yaml
temporal_provenance:
  event_time: 사건이 실제로 발생한 시각
  published_at: 최초 기사·공시가 공개된 시각
  available_at: 시스템이 합법적으로 이용할 수 있게 된 시각
  retrieved_at: 시스템이 실제로 가져온 시각
  decision_time: 에이전트가 판단을 확정한 시각
  order_time: 주문을 제출한 시각
  fill_time: 주문이 체결된 시각
```

백테스트에서 사용 가능한 데이터의 조건은 다음과 같다.

[
available_at
\le
decision_time
<
order_time
\le
fill_time
]

이 조건을 만족하지 않으면 미래 데이터 사용 또는 비현실적 체결 가능성을 조사해야 한다.

## 주문 원장을 별도로 둬야 하는 이유

LLM의 최종 판단과 실제 체결은 서로 다르다.

```text
LLM 판단
BUY, 목표비중 20%
        ↓
위험 규칙
최대비중 10%로 축소
        ↓
주문 엔진
지정가 주문 100주 제출
        ↓
호가창
60주만 부분체결
        ↓
실제 포지션
목표비중 6%
```

따라서 다음을 분리해서 저장해야 한다.

```yaml
decision_action:
  target_weight: 0.20

risk_adjusted_action:
  target_weight: 0.10

submitted_order:
  quantity: 100

executed_order:
  quantity: 60
```

최종 성과는 LLM이 제안한 목표 포지션이 아니라 실제 체결 결과로 계산해야 한다.

## 이 논문이 자동매매 설계에 주는 핵심 시사점

### 1. 리서치 결과와 주문 실행을 분리한다

```text
LLM 분석
  → 투자 의견
  → 정량 위험 규칙
  → 목표 포지션
  → 주문 생성
  → 호가창·체결 시뮬레이션
  → 실제 체결 원장
```

LLM은 주문 엔진이 아니라 근거 생성 및 의사결정 보조 계층으로 두는 것이 적절하다.

### 2. 백테스트마다 입력을 동결한다

```text
가격 CSV
뉴스 원문
재무 데이터
검색 결과
모델 응답
프롬프트
도구 응답
```

모든 입력에 해시를 부여해야 나중에 동일 실행을 감사할 수 있다.

### 3. 비용을 하나의 고정 수수료로 끝내지 않는다

[
TotalCost_t
===========

Commission_t
+
Spread_t
+
Slippage_t
+
MarketImpact_t
+
Tax_t
+
BorrowCost_t
]

유동성, 주문 크기, 변동성에 따라 비용 시나리오를 달리 적용해야 한다.

```yaml
cost_scenarios:
  optimistic:
    commission_bps: 1
    spread_bps: 2
    slippage_bps: 1

  normal:
    commission_bps: 3
    spread_bps: 5
    slippage_bps: 5

  stressed:
    commission_bps: 5
    spread_bps: 15
    slippage_bps: 25
```

### 4. 체결 시점별 결과를 모두 비교한다

```text
same_close
next_open
next_vwap
next_close
1분 지연
5분 지연
30분 지연
```

한 가지 실행 규칙에서만 수익이 발생한다면 모델의 예측력보다 체결 가정에 의존한 결과일 수 있다.

### 5. Gross와 Net 성과를 반드시 함께 보고한다

```yaml

  gross_cumulative_return:
  net_cumulative_return:
  total_turnover:
  total_commission:
  total_spread_cost:
  total_slippage:
  cost_drag:
```

## 논문의 한계

### 리뷰 자체의 한계

* 2023년부터 2026년 5월까지의 제한된 검색 구간이다.
* 빠르게 변하는 arXiv 연구를 대상으로 하므로 논문과 코드 상태가 바뀔 수 있다.
* 공개 자료만 평가하므로 비공개 구현은 반영하지 못한다.
* `Y/P/NR` 세 단계가 서로 다른 연구의 세부적인 품질 차이를 압축한다.
* 직접 매매, 알파 발굴, 포트폴리오 벤치마크처럼 성격이 다른 연구를 같은 핵심 항목으로 비교한다.
* 두 저자가 합의했지만 외부 독립 평가자가 수행한 블라인드 감사는 아니다. ([arXiv][2])

### 예시 실험의 한계

* 미국 대형주 10종목만 사용한다.
* 고정된 현재형 유니버스이므로 생존자 편향을 완전히 제거하지 못한다.
* 실제 LLM을 호출하지 않는다.
* 기업 이벤트가 뉴스가 아니라 가격 급등락으로 만들어진 대리변수다.
* 실제 시장충격을 계산하지 않는다.
* 호가창, 지정가, 부분체결을 구현하지 않는다.
* 0·10·25 bps의 단순 비례 비용만 적용한다.
* 주식 외 자산과 다른 시장 국면에 일반화할 수 없다.
* 점수 계수와 0.35 임계값의 선택 근거 또는 독립적인 튜닝 구간이 본문에서 충분히 설명되지 않는다.
* 실제 LLM 에이전트가 같은 전략 순위를 재현한다고 주장할 수 없다. ([arXiv][2])

## 재현성 자료 공개 상태

논문은 다음 자료가 함께 제공되는 LaTeX 프로젝트에 포함돼 있다고 밝힌다.

```text
논문 소스

30개 연구 증거 행렬
연구별 코딩 노트

```

다만 논문과 arXiv 메타데이터에는 독립된 공식 GitHub 저장소 주소가 명확하게 제시되지 않는다. 따라서 현재 확인 가능한 공개 기준점은 arXiv 원문과 TeX Source다. 저자들도 예시 실험을 상업용 외부 데이터 피드까지 포함한 완전한 end-to-end 재현 패키지로 주장하지 않는다. ([arXiv][2])

## 핵심 평가

이 논문의 가장 중요한 기여는 새로운 트레이딩 기법이 아니다.

**LLM 트레이딩 논문을 평가할 때 에이전트 역할과 추론 품질보다 먼저 확인해야 할 실행·재현성 기준을 구체화했다는 점**이 핵심이다.

```text
좋은 설명
≠
재현 가능한 매매

높은 백테스트 수익률
≠
실행 가능한 수익률

코드 공개
≠
완전한 재현성

복잡한 멀티 에이전트
≠
엄밀한 평가
```

TradingAgents나 FS-ReasoningAgent를 실제 시스템에 적용할 때는 에이전트의 분석 결과만 저장해서는 부족하다. 최소한 다음 네 종류의 원장이 별도로 필요하다.

```text
1. 입력 시점·원문 출처 원장
2. 모델·프롬프트·도구 실행 원장
3. 판단·위험 승인 원장
4. 주문·체결·비용 원장
```

논문의 메시지를 한 문장으로 정리하면 다음과 같다.

> **트레이딩 에이전트가 왜 매수했는지를 설명하는 것만큼, 그 정보를 언제 알았고 언제 어떤 가격과 비용으로 체결됐는지를 설명하는 것이 중요하다.** ([arXiv][2])
