# TradingAgents 구현체 안내

## 자료 성격

이 문서는 논문 요약이 아니라 `TauricResearch/TradingAgents` 저장소의 구현·실행 참고다. 관련 논문은 [02_트레이딩팀.md](02_트레이딩팀.md)에 정리했다. 저장소는 계속 변하므로, 논문의 실험 코드와 현재 기능을 같은 것으로 가정하면 안 된다.

- 저장소: <https://github.com/TauricResearch/TradingAgents>
- 확인 기준: 2026-07-12의 README / 설치 안내
- 라이선스: Apache-2.0

## 현재 구성

저장소는 분석가, 강세·약세 연구원, 트레이더, 위험관리 역할을 조합해 종목 분석과 거래 결정을 만든다. `cli/`, `tradingagents/`, `tests/`, `scripts/` 구조를 두고 CLI와 테스트를 제공한다. 최근 릴리스에는 데이터 접근 계약, 다수 LLM 공급자, FRED·Polymarket 데이터 공급자, 재시작 가능한 그래프 실행, 크립토 심리 데이터 소스 등이 추가돼 있다.

## 설치 흐름

README의 기본 흐름은 다음과 같다.

```bash
git clone https://github.com/TauricResearch/TradingAgents.git
cd TradingAgents
conda create -n tradingagents python=3.12
conda activate tradingagents
pip install .
```

Docker를 쓸 때는 `.env.example`을 `.env`로 복사해 필요한 키를 넣고 `docker compose run --rm tradingagents`를 실행한다. 로컬 Ollama 프로필도 별도로 제공한다.

## 공급자와 키 관리

OpenAI, Google, Anthropic, xAI, DeepSeek, Qwen, GLM, MiniMax, OpenRouter, AWS Bedrock, Ollama와 OpenAI 호환 서버를 지원한다. 시세 데이터에는 Alpha Vantage 키가 필요할 수 있다.

현재 프로젝트의 `.env`에는 실제 비밀값을 두지 않고, 다음 원칙을 지킨다.

- 키를 소스·노트북·로그·프롬프트 출력에 남기지 않는다.
- `.env.example`만 저장소에 공유하고 실제 `.env`는 버전 관리에서 제외한다.
- 실행 로그에는 `키 존재 여부`와 `공급자 이름`만 기록한다.
- 실거래 권한 키와 읽기 전용 데이터 키를 분리한다.

## 도입 전 확인할 사항

1. **데이터 시점**: 현재 버전의 데이터 공급자가 실제로 당시 시점 정보만 반환하는지 확인한다. 특히 뉴스와 감성 데이터의 룩어헤드 방지가 중요하다.
2. **주문 연동 범위**: 분석·권고 도구인지, 실제 브로커 주문까지 연결되는지 코드를 기준으로 확인한다. 테스트 계좌/페이퍼 트레이딩부터 시작한다.
3. **비용과 지연**: 여러 역할의 LLM 호출은 장중 주문에 느릴 수 있다. 호출 수, 재시도, 타임아웃, 최대 비용을 사전에 제한한다.
4. **재현성**: 모델 ID, 프롬프트, 데이터 공급자 응답, 실행 날짜, 설정 파일을 고정·기록한다.
5. **업스트림 변경**: README의 최신 명령과 논문 당시 명령이 다를 수 있으므로 특정 커밋을 고정해 검증한다.

## 이 저장소를 현재 자동매매 프로젝트에 붙일 때의 권장 경계

TradingAgents는 `매매 아이디어/리서치 생성` 레이어로 두고, 실제 주문은 별도의 결정·리스크 레이어가 받아야 한다.

```text
TradingAgents 분석 보고서
  -> 정규화된 신호(방향·근거·신뢰도·유효시각)
  -> 자체 리스크 한도·중복 신호·시장 상태 검사
  -> 주문 생성
  -> 브로커/거래소 실행 및 체결 원장
```

이렇게 분리하면 외부 프레임워크의 오류, API 지연, 형식 변경이 주문 실행으로 곧바로 전파되는 것을 막을 수 있다.
